## Counterexamples to small-looking workarounds

- **Two copies/import identities:** original Set A holds a late read/close while copy B sees empty Set and starts9-file I/O. Module-level uniqueness is not process-wide uniqueness across independently bundled/module-cached copies. A second gate is not the original guarantee.
- **Outer mutex around legacy Promise:** the Promise may reject with cleanup pending while original owner continues. Release-on-reject permits concurrent v3 I/O. Retain forever rejects even after late cleanup succeeds because the public API has no live settlement notification. Polling via dummy reads or resetting owner is not an equivalent solution.
- **8+1 calls:** the old function owns a distinct lifecycle per call, so parent namespaces are not checked as a single9-file acquisition. Two deadlines would additionally reset budget. Reusing just the deadline still does not fix the ownership/namespace gap or lost raw bytes.
- **Append raw export/shared owner and keep77b1:** executable file hashes and readerExecutionIdentity change. This is a new closure even if every old test still passes.
- **Overwrite v2 mapping with new closure:** SQL parent mapping equality and app validateCompleteResponse reject old replay before it reaches its stored row. Accepting arbitrary historical hashes without exact version membership would weaken those checks.
- **Append historicalCash to existing v2 material:** closed schemas reject new keys; old author assignment/result contracts reject a new schema. Retagging a cash-only leaf as complete scenarios loses the original full workload. Whole carrier931023/353803 belongs only in private local memory, never in the8192 request or262144 material.

## Recommended minimal version boundary (PROPOSAL; needs approval)

Separate three identities: (a) historical sealed material's original closure/inventory/schema; (b) current replay-validator/application execution identity; (c) newly executed full v3 calculation closure. Do not rewrite (a) to (b), or claim that a new validator executed old77b1 calculation.

1. Preserve historical22-file/old-mapping/old-artifact manifests as immutable version records. If original fresh-v2 executable behavior must remain callable, it needs an exact old execution+artifact layout. It cannot be modified to share the new private owner while remaining byte-identical. A separately supervised process realm could serialize whole-worker lifetime, but that is a larger explicit lifecycle architecture with exit/recovery proof, not the minimum module refactor, and is not recommended for the next slice.
2. Preferred current executable: extract one ownership implementation and one bounded filesystem engine from the actual old logic into a NEW closure. Suggested ownership files: `research-financial-read-owner.ts`, `research-financial-read-engine.ts`; a narrow legacy≤8 facade plus a new fixed-profile9/7 facade share that same injected singleton instance. Do not also deploy/call the archived private-Set reader on a live acquisition path. Registry construction belongs to one server composition root; all readers require its token. Prove module/bundling topology and reject accidental second instance, rather than assume two imports share a singleton.
3. Pending opens/reads/closes, retained buffers and error cause live in that one owner, not in facade wrappers. Register before open; preserve once-only close and late-write wipe. Fail/timeout does not release the slot. Late successful settlement releases automatically; cleanup failure retains a truthful recovery-required state until validated controlled recovery, not blind unlock. Both version facades are blocked while pending. The same monotonic10s deadline encompasses the whole request and final namespace/lease checks; no reader-created replacement deadline when one is supplied.

Wipe raw/carrier copies including late writes. Capacity1MiB raw/512KiB file/160000 projection/262144 material/depth12 remains; measure complete scenario+cash output and canonical charge before proposing a schema. Cash leaf output alone does not prove those combined bounds.
5. Compatibility dispatch needs an explicit finite reviewed registry keyed by version plus exact closure/inventory identity, not latest symbol or caller-selected path/hash. Marker2 replay must keep the old request shape, canonical request/hash, row bytes/IDs, timestamps, source revocation/completion/lease rejection and old schema verification.
