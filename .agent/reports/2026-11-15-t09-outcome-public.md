# T09｜股票詳情的上榜後成效

候選補丁將「上榜後成效」加入股票詳情。頁面沿用原來的凍結榜單、股票和研究版本。跨榜單或版本不符時不讀成效。既有 `/api/launch-ranking` GET 只在單一已發布股票的詳情回應加入 `outcome`，並保留原來的無快取設定。

顯示兩套基準。研究使用發榜日收盤價。成交模擬使用次一交易日的開盤驗證，顯示成本前及扣除成本的結果。兩套都使用 20／60／120 個交易日視窗。首次上榜、連續上榜、資料缺口、尚未到期、觸價順序不明和無法成交都有明確狀態。零報酬以 0% 顯示。

成效 RPC 只讀同一榜單已保存且可知的最新版本。這個 RPC 只輸出經選取的日期、狀態、數值和版本識別。原始輸入、成交權限證據、內部運行記錄和私人內容保留在內部。舊榜單沒有成效記錄時顯示尚未納入追蹤。公開 GET 不建立訊號、不觸發研究，也不呼叫模型。

## 隔離驗證

- PostgreSQL 17.11 驗證原榜單綁定、未排名標的無資料、讀取不寫入、最新更正版可見、匿名與登入角色無直接資料庫存取、內部嵌套測試字串未進公開結果。
- 12 個 Node.js 測試執行實際路由、股票詳情選擇和 React HTML 渲染。測試涵蓋空、無法成交、零報酬、未知、成本前後及 20／60／120 日欄位。相關讀取器、元件與測試通過 TypeScript 5.9.3 嚴格型別檢查，補丁套用與檔案雜湊一致。
- 測試使用臨時資料庫及合成行情。Next.js 的完整建置、實際瀏覽器桌機／手機驗收、開盤成交正例及依首次與重複上榜分組的彙總仍待完成。正式服務未變更。

先套用 T09 評估器，再套用 `launch-outcome-public.patch`。SQL `launch-outcome-public-read.sql.txt` 依賴訊號表與不可變成效版本表。原生驗證 runner 的前九個參數與成效版本驗證相同，第十個參數為這份讀取 SQL。
