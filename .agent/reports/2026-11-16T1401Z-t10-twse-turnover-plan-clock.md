# T10 上市成交額的截止前規劃

11549 的規劃與直接排入路徑將函式內稍晚讀到的時鐘傳入交易日讀取器。讀取器只接受截至 PostgreSQL 語句起點可知的交易日資料，因此即使已有合法的同日收盤紀錄，規劃器也會略過 11549，而直接排入會拒絕。兩處交易日檢查改用語句起點。實際觀測、租約、截止和 ready 收據的時鐘沿用原規則。

Contabo 的現行 20:15 台北時間 final-freeze timer 已存在，其受保護的佇列排空路徑包含啟用條件下的來源預處理。驗證當日該服務的執行退出碼為零。此次只修程式，未安裝或改動 timer，也未宣稱現行正式版已執行新來源。

隔離 PostgreSQL 17 重現舊版未排入、手動要求失敗。在同一 SQL 程序及既有佇列中，修正版排入一筆、重跑同一筆、優先領取、解析 CSV、保存成交額，在下一筆已提交的請求取得 ready 收據，重跑回傳原收據。來源未完成時沒有 ready 收據，查詢未來 cutoff 仍被拒絕。五支既有程式組成的來源函式及兩處時間修正由雜湊核對，函式所有權與權限維持原值。測試使用隔離授權及測試 CSV。

額外 20 項排程與來源回歸、Next.js 16.3.4 production build、TypeScript 及 92 頁靜態輸出通過。正式 writer 的實際收據、真實 20 日窗口及榜單驗收仍待完成。
