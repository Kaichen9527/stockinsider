# T18 使用還原端原始 psql 參數驗證

Contabo 使用之前成功的來源保管和一次性標準輸入交接。首度執行新版固定組的正式備份回放進入 PostgreSQL，隔離資料庫單元退出 2。舊收據取用器只接受單一記錄，漏掉正式 runner 可回傳的「執行摘要＋拒絕」。已另外確認三個單元結束與工作映像清理，並調整本次取用器可記錄兩類去敏欄位。正式回放的明確階段與驗收仍待原參數的對照重跑。

重現發現實際 owned-clone callback 用 `psql -X -A -t`，先前原生測試用 `-qAt`。前者在唯讀交易會產生 `BEGIN`、查詢列、`COMMIT`。此格式會被新版 schema、head 和凍結綁定查詢的嚴格解析拒絕。只在三個固定查詢啟用 psql QUIET，保留唯讀交易和既有 callback。舊 profile 不變。

- 7 個 PostgreSQL 17 測試通過，專門比較正式 callback 的參數、交易輸出及 schema 缺口。另用同一參數實測最小隔離 schema 的六種狀態與已發布範例的精確 JSON 綁定。
- 把缺合格資料的狀態照原規格保留為缺口。此修正不授權發布、運行來源 writer 或改正式服務。
