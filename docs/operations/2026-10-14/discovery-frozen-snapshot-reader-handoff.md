`readDiscoveryFrozenSnapshot` accepts a new unconnected dedicated client and one lowercase UUID. It owns connect, one REPEATABLE READ READ ONLY transaction, timeout configuration, normal/failure ROLLBACK and client end. The same client is permanently consumed, including failure; it cannot be shared/reused. A browser/non-Node invocation is rejected. There is no connector, configuration, credential, environment selector or CLI. The caller must create/inject this dedicated client later from an already authorized server/operator context.

Every SQL statement and column list is fixed; only exact run/manifest UUID parameters vary. Timestamps are selected using PostgreSQL UTC `to_char` with six fractional digits, not pg's JS Date parser. Actual `transaction_read_only`, isolation and `pg_current_snapshot()` identity are verified before/after transfer. All nine named relations must exist as real tables and `row_security_active` must be false; a caller with an RLS-filtered visible population is rejected, not counted as complete. This check grants or bypasses no privilege.

Scope: ALL retained revisions, source authorities, publisher authorities and family registry, including newer invalid/inactive/future rows. Verification scope is the exact run; manifests and all sections/rows are the exact uniquely bound publisher manifest. Run and publisher input uniqueness/frozen state are checked first. The unchanged pure reader performs retained-head, 64/stream, complete manifest/page/hash, clock and output-binding validation. Full packet and output serialization retain4MiB limits.
