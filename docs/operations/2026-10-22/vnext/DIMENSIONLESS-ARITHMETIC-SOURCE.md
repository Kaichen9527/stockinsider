# Dimensionless arithmetic — finite source candidate

The original financial request contract represents `pe_multiple`, `pb_multiple`, `ev_ebitda_multiple` and `ev_sales_multiple` with unit `dimensionless` (`web/src/lib/opportunity-v3/request-values.ts`). The vNext claim validator previously recognized only `ratio` and `multiple` as scalar multiplier/divisor units. This candidate accepts the existing `dimensionless` unit directly; no source value, financial fact, unit label, period, receipt, model input or acquisition authority is rewritten.

TypeScript changes only the two scalar allowlists in `validateClaim`. Multiplication still requires exactly one non-scalar operand whose unit exactly equals the output unit, including scalar-first order. Division remains exactly two operands: equal-unit division may yield `ratio`, or a scalar denominator preserves the numerator's exact unit. Addition/subtraction, incompatible cash/share units, period equality, finite numbers, cited original IDs, zero-denominator rejection and arithmetic tolerances remain unchanged. `TWD` cash flow cannot become `TWD_per_share` through this change. Neither `TWD/share` nor `TWD_per_share` is globally relabelled.

The output-unit tightening makes SQL match the existing TypeScript rule: the old SQL `ANY(units)` check could incorrectly accept EPS times ratio with output `ratio`; accepting dimensionless without fixing that would expand the same defect. All valid original ratio/multiple operations remain valid. Exact inverse parity and successor hash fence the three edits.
