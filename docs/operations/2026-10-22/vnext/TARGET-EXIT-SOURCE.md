## Baseline versus entry valuation

`reviewedTargetBaseline` validates the immutable original artifact/claims/formulas/original-source hashes and recorded review using its original quote. It preserves the originally reviewed base/bear/bull/method after a later quote crosses the base. `reviewedValuation` and all entry/publication gates remain byte-for-byte unchanged. A current quote cannot erase the original target by making remaining upside nonpositive.

The SQL checker independently revalidates original claims and per-claim reviewer source hashes, distinct author/reviewer principals, executions and external response IDs, durable completed normalized outputs, frozen request hashes/contents, source-read ordering and original execution deadlines. It resolves the original reviewed quote from actual cached observations as of the original publication. That quote must bind the exact original evidence observation ID/value/session. It then derives the current completed quote and the intervening corporate-action evidence separately. An original120-second execution/qualification window is not a new target lifetime; no overall financial-entry qualification Boolean is required or fabricated. Missing usable original reviewed scenarios still defers.

An expired or withdrawn source policy, per-content withdrawal, changed member input, different current publication, contraindication, or incomplete current source identity blocks the check through the existing current-source predicate. No new target expiry is invented. The source contains no general assumption that arbitrary numeric financial scenarios are lawful receipts.

## No newer thesis — exact bounded meaning

The checker requires the latest actual publication and unchanged member/job/preparation input. Any queued/running/authored/reviewing work defers, labelled pending work rather than an independently approved thesis. Audits after the baseline reporting changed verified financial inputs, new permitted original content or a changed published claim/period also defer. A later quote, technical observation or market observation alone is not a new investment thesis. No conclusion about absent external news is drawn from bounded/incomplete source scans.

At current close greater than or equal to the reviewed base, the operator-only server RPC calls the existing exit branch under advisory mutex64221022. That branch re-runs the private current checker and requires the exact deterministic proof and evidence hash. A direct service-role `exit` request with only `target_hit` and an arbitrary evidence string is refused. Membership/home/confirmation/history handling remains the original exit implementation; existing pending-work policy is preserved rather than silently cancelled or refunded by this producer.

The lookup uses only original cached `stock_instruments_v3`, `tw_trading_sessions_v3`, `opportunity_price_observations_v3` and the three original `opportunity_corporate_action_*_v3` relations. It rejects conflicting heads, future clocks, missing baseline/current completed sessions and unbounded lookups. No weekday calendar or forward session is invented.

The original corporate-action snapshot is scoped to one exchange/session/session-authority ID, not a declared multi-day coverage interval. Every completed official session strictly after the original quote through the current quote therefore needs its actual selected snapshot and three named feed receipts. The checker verifies full declared counts, ordered event rows, original source-row references and dataset hashes. A corporate action for another symbol is not itself a target rebase. Any intervening action for the target symbol defers with `target_rebase_after_corporate_action_unavailable`; cash events are not silently treated as share splits.
