# Same-build browser regression source

The existing isolated browser launcher now supports the ordinary Ubuntu hosted job as well as Codex Linux. This is a source candidate; the new runner/binary combination is NOT_RUN until its own ordinary CI result. Previous Chromium151 VM screenshots and the original Playwright CDN403 retain their own subjects. No browser download/install, production connection, staging acceptance or source/model approval is added.

The runner requires the original Node22.14 binary SHA, an explicit `VNEXT_BROWSER_BUILD_SOURCE_SHA` equal to the clean runtime checkout, and the already-completed build ID/server-file hash. The only browser selectors are the existing `/usr/bin/chromium` default or hosted `/usr/bin/google-chrome`; it records both the installed launcher and actual browser ELF SHA and actual version. It preserves inherited proxy/CA settings. `E2E_BASE_URL` and `PLAYWRIGHT_SKIP_WEBSERVER=1` continue to select the owned loopback Next server without the default `.env` webServer recipe.

The ordinary job uses its earlier actual PostgreSQL business snapshots for the unchanged twelve desktop/mobile UI cases. It separately derives four current/withdrawn snapshot files from that same run's guarded thesis RPC payloads, preserving every payload field, for the unchanged two desktop/mobile current-article/rights cases. These are synthetic source/provider fixtures. The transport serves captured actual database results; it does not claim live browser-to-PG queries, real financial/model evidence, current production authority or an independent semantic review. No previous private snapshot is borrowed.

Admission requires the original8GiB floor plus a256MiB next-browser workset reference on the actual checkout filesystem and/tmp. This reference is not a future upper bound. Runtime half-second samples check both original floors and the owned launcher/Next/Playwright/Chrome tree RSS<8GiB. A resource breach, unavailable observation, deadline/containment or live original PID after cleanup is nonzero. PID1 zero-RSS zombies are recorded as zombies, never absent; sampled RSS is not an instantaneous peak. No container, cache, source, data, screenshot or historical evidence is removed.

Only finite acceptance summaries and validated PNG screenshots from this known synthetic fixture are uploaded. Full Playwright JSON, traces, random internal bearer/control keys, app logs and raw snapshots remain private. The summary preserves actual case/project statuses, binary/source/build/snapshot hashes, resource minima and process settlement. Missing installed browser, missing same-run snapshots, a skipped or failing case, or unknown cleanup is not a green browser acceptance.

Source-only checks cover Python AST/compile without pycache, YAML and bash/embedded-Python syntax. The browser specs and their expected counts/content/locators are unchanged. Actual hosted/browser acceptance remains a separately recorded result; no local fullbuild/browser workload was started at the limited workspace margin.
