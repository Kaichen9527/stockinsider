# Durable bounded cache-window worker candidate

The HTTP `source-extract` and explicit postclose cycle now select `source-window-worker.ts`. The original source-worker and exact TWSE snapshot runtime closure remain byte-identical; no old pin is replaced. No new SQL, role, table, grant, source authority, HTTP credential or model provider is introduced.

The new worker holds the existing analysis writer lease throughout cache enumeration, original extraction RPCs and progress append. It accepts only configured operator identity, rejects disabled mode before IO, and has no caller cursor/root/clock/provider selector. Only PTT metadata and the original official cache scope are selected after current source policy. Telegram/InvestAnchors raw content is never selected. PTT projection omits body entirely.

Each permitted feed reads at most200 current cached rows, ordered by actual `(published_at,id)` descending. Its existing run-ledger namespace `vnext-cache-ptt` / `vnext-cache-official`, parser `vnext-cache-keyset-v1`, contains a closed rights/principal/cutoff-bound progress record. A complete accounted page advances a stable keyset cursor, preserving PostgreSQL microsecond ordering; budget-limited/unaccounted pages hold their exact prior cursor. Duplicate raw IDs with the same original semantic identity share one extraction. The shared original SQL200/day,50/source ledger remains the only new-work authority. There is no parse/model/budget authority in a cursor record.

Original content identity and extraction behavior are unchanged: the only224-byte insertion in `permitted-content.ts` exports its existing cheap validated fingerprint, without extraction/reservation. Unknown completion stops before progress append. An uncertain append propagates once without retry; a later explicit run reads durable progress and original extraction receipts before acting. Current rights changes or a30-day-old cache cycle restart enumeration without deleting or resetting extraction history/quotas. Unknown/malformed/ambiguous progress refuses before cache reads.

This is **cache traversal**, not upstream exhaustive acquisition or an atomic multi-query source snapshot. Late corrections are considered in a subsequent pass; expired/incomplete cycles remain gaps. Existing upstream pagination/conservation contracts, real rights, connector outages and comparable28-day coverage are still not established. Every progress row deliberately reports `terminal_reason=partial`, `content_analyzable=false`, `index_updated=false`, `succeeded_at=null`, acquisitionAttempted=false, eventCoverage=unknown and eventVolume=null. Cache enumeration never manufactures volume zero or independent roots. The existing snapshot receipt projection remains separate.

Initial TS2737/TS2352 RED is preserved; BigInt constructor avoids changing compiler target, and the two literal source projections retain a runtime-validated row seam. No native PG/HTTP/lease/real source acceptance is claimed for the cursor write path yet. Original VM heavy PG/build/browser remains NOT_ADMITTED; new source ordinary hosted CI will have its own exact subject and evidence.
