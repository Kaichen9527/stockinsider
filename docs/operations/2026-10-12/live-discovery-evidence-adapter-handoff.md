## Implemented boundary

The server audits its existing returned seven-day mention pages BEFORE eligibility filtering, source dedup or eight-link display truncation. Pagination remains750 with100000-row hard bound/requireComplete; stable available_at/id order is retained. A requireComplete option does NOT establish exhaustiveness: a server cap100/request750/actualtotal200 produces100 returned rows. This slice passes rowsComplete:false and emits mention_window_incomplete until an independent exact-count or stable completion receipt is available. New select fields are existing id/raw FK/as_of/created_at. HistoricalOnly's limit5000 rows are deliberately not treated as the current complete window. No extra DB query is introduced. Full rows grouped once by stock, avoiding per-card full-plane scans.

Adapter TW four-digit stocks only:512 rows per stock,8192 selected logical-view bytes per row,1048576 aggregate selected logical-view bytes. Unknown metadata is not serialized/read by getters. These are adapter logical projection bounds, NOT HTTP/raw-table storage bounds. Overflow returns unsupported with explicit examined/unexamined accounting; never truncated-success. Each row has a disposition and scoped candidate-mention UUID. Raw FK is never substituted for normalized source identity. Database created_at/available_at/as_of/mentioned_at are independently checked against explicit cutoff with microsecond precision, preserving input clock strings; publisher precision is not guessed. Mutable legacy rows cannot prove historical snapshot contents, recorded explicitly.

PTT diagnostic grouping uses conversation URL only to prevent cross-post pooling, never as an independent root. Counts require the actual bounded excerpt ticker with alphanumeric boundaries, exact SHA, local-match basis, matching symbol, parent/index/fragment, author and successful bounded body read. The row source_url must exactly equal retained document_url. All received rows for one (parent,index) are grouped before author counting. Exact duplicates count once; any differing normalized author/text/hash invalidates the whole key in either order (including repeated row UUIDs). An invalid/retracted bound instance also blocks that key. The grouping key is conversation membership, not an independent news root. Reactions/emoji/title-only/name-only/foreign-stock/hash mismatch do not count. Repeated authors are deduped within one post. Withdrawn mention excluded; unknown raw/root withdrawal heads prevent any admission.

Every mapped DiscoveryEvidence remains complete:false/pttArticles:null for this actual legacy contract, with concrete missing-head/body/root reasons. This is data-backed unsupported, not a fabricated usable null/stub. Server projects only a compact discoveryEvidenceAudit (counts/cutoff/gaps), not private identities or retained text.
