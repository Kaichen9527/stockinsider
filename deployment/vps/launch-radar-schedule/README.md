# Launch radar schedule candidate

These three systemd units are held for the reviewed launch release. The legacy installer reads units from `deployment/vps/systemd`. Install the candidate units together as a replacement during the release cutover, after the writer, data-plane manifest and server routes have passed the release gates.

- `stockinsider-research-cycle.timer` is the single timer for market background at 08:15, queued research at 20:55 and publication at 21:30 Asia/Taipei.
- The candidate `stockinsider-research-cycle.service` takes the same write lock as the other production jobs. The runner checks the actual Taipei wall time after acquiring the lock. A missed morning run after 09:00 defers. An evening run drains the current date's final queue and checks that date again before requesting the protected launch cycle. A same-session final data gap returns a retained outcome without requesting a new rank. Transport, writer, or unexpected response failures still fail the job. The server and database enforce official trading dates, the fixed cutoffs and eligible snapshots.
- The 20:55 slot dispatches already-admitted launch research through the shared writer, queue, and ledger. It checks both venues and the final data queue after the existing reconcile run, requires bound author and reviewer credentials with the v5 profile, and stops beginning work at 21:10. Set STOCKINSIDER_LAUNCH_RESEARCH_DISPATCH_ENABLED=true only after confirming scheduled use of the existing model allocation. The slot defers when final data is unavailable. Publication still reads reviewed results frozen by 21:30.
- When today's research ledger date is absent, the dispatch and publication paths can synchronize it from the existing official calendar through the shared writer. The sync requires both completed venue heads for today's Taipei date. At publication it also requires both venues to have been known by 21:30.
- At the publication slot, the same runner checks the weekly thesis ledger before draining the final queue. The first admitted trading session of the Taipei week checks all current members. When a member or its input changes, the next admitted slot checks the current pool. The audit uses cached evidence and the existing writer lease. Its result is separate from rank publication.
- When Gmail capture is enabled, the 08:15 run scans missed days and the current day. The 21:30 run checks current-day notices after the publication attempt, including a retained ranking or a job error. Both use the same private notice progress and daily budgets. The evening check defers close to Taipei midnight so the next morning can catch up. Notice receipts grant no article or ranking authority.
- The candidate `stockinsider-taiwan-data-preliminary.service` keeps the existing data refresh and preliminary drain. Its existing timer and the data freeze and reconcile units remain part of data preparation.
- Both candidate services require the vNext and launch rank feature flags. The server independently rejects the launch-only action when the launch policy is disabled. The runner reports only its slot, date and result class.

Before cutover, compare the effective installed units and overrides with the reviewed release. Verify the selected worker understands the launch route, the protected writer credentials are bound, and no older schedule can publish independently. Restore all three prior definitions as part of the release rollback. Verify the weekly audit on the deployed worker and confirm real publication admission as part of the release gates.
