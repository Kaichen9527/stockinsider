# Internal Principal Contract: source-led-opportunity-engine-v3

Version: `internal-principal-v3.8`

## Dual control with legacy bearer auth

Legacy `requireInternalAuth()` remains unchanged for legacy routes. V3 control/worker routes and the exact eight runner-ingestion routes below may accept that bearer alone only as the fixed non-human `opportunity_runner` principal and only for their closed operations. A bearer-only request can never submit a manual alias approval, publisher approval, discovery identity approval, peer authority, valuation verification, assistive-artifact registration, link-audit label or adjudication.

Every V3 human-authority route, including all human-authority Supabase writes and the four blinded assignment/label routes, is dual controlled: it first invokes the repository-governing `requireInternalAuth(req)` guard and also requires `requireInternalPrincipalV3()` with an actor-bound signature. Neither guard substitutes for the other. The authentication headers are exactly:

```text
Authorization: Bearer <INTERNAL_API_KEY>
X-StockInsider-Key-Id
X-StockInsider-Timestamp
X-StockInsider-Nonce
X-StockInsider-Signature
```

Human-authority POST routes require a non-empty `INTERNAL_API_KEY` and reject `X-Internal-Key`, `CRON_SECRET` as the presented token, multiple `Authorization` values, a non-Bearer scheme and any bearer unequal to that exact key. After that exact-shape/value precheck, route code must call and inspect the unchanged `requireInternalAuth(req)` helper before accepting the signed principal; the helper's `CRON_SECRET` fallback remains available to legacy/GET cron routes but can never authorize a human-authority POST. The bearer is only the repository-wide internal-endpoint guard; it never supplies `principalId`, role or stored actor. The signed principal is the sole human identity/role source. Route code must never copy legacy helper error text to a response and must not access Supabase unless both controls pass.

The server owns a secret mapping from key ID to `(principalId,roles,HMACKey,validFrom,validTo,status)`; it is loaded only from server secret storage and never from request JSON, public environment names or a database row writable by the caller. Roles are exactly `opportunity_runner|source_reviewer|identity_reviewer|publisher_reviewer|peer_reviewer_admin|peer_reviewer|valuation_reviewer|model_reviewer|link_reviewer|link_adjudicator`.

The non-secret authorization half is the database-authoritative, app-immutable `internal_principal_role_bindings_v3` relation in `storage-schema-contract.md`. Every server mapping entry is usable only when its exact `(principalId,role)` also has one cutoff-valid active binding at the database transaction timestamp. The additive V3 schema migration creates the empty relation and no production binding. Bindings are provisioned only by a later explicitly reviewed binding-data migration executed by the database migration owner from an approved non-secret principal/role manifest; test fixtures may seed them only as the migration owner. `service_role`, request handlers and every V3 RPC have zero insert/update/delete authority over them. Until that separately approved production migration exists, all V3 caller-bound operations fail closed and the scheduler remains disabled. A secret mapping without a binding, a binding without a secret mapping, an expired/revoked binding, zero matches or conflicting eligible bindings fails closed as `principal_role_unavailable`. This deliberate dual control lets each RPC distinguish an authorized principal/role from an arbitrary UUID even though the HMAC key itself never enters the database; this architecture amendment does not authorize a production binding-data migration.

The timestamp is UTC RFC-3339 whole seconds and must be within 300 seconds of server time. Nonce is 16..64 lowercase hex. `bodySha256` is SHA-256 of the exact request-body bytes, including the empty body. `canonicalPath` is the literal server allowlisted pathname for the matched route: ASCII, begins with one `/`, has no query/fragment, percent escape, dot segment, duplicate slash or trailing slash. Human-authority routes accept no query parameters. The signed UTF-8 preimage is RFC 8785 canonical JSON of `["internal-principal-v3.8",keyId,principalId,method,canonicalPath,timestamp,nonce,bodySha256]`. Signature is lowercase HMAC-SHA-256 hex and is compared in constant time. The shared bearer is deliberately not a preimage member: possession of both independent credentials is checked at the request boundary, while bearer rotation does not invalidate signed-principal identities. The principal ID used in storage is always the verified mapping value; an `actor`, `reviewer`, `approvedBy` or `principalId` body field is rejected as an unknown field.

For every V3 human-authority route, the outer request precedence is fixed: (1) literal route method/query/raw-size/media-type constraints; (2) the exact bearer shape plus `requireInternalAuth(req)`, followed by the complete signed-principal envelope; (3) exact body schema and route branch; (4) `getOpportunityV3ServerClient()` acquisition; (5) nonce/operation RPC processing. The response family is selected only by the already matched literal route and never by failure state: the seven non-blinded routes use `error:'v3_internal_request_rejected'`; the four blinded link routes use `error:'link_audit_request_rejected'`. The blinded specialization is authoritative for all five steps and unknown errors on those four paths; the non-blinded literal never appears on a blinded response and vice versa.

For steps 1 through 4, both families use RFC-8785 canonical JSON with exactly keys `code,error` plus `Cache-Control: private, no-store`. Step 1 or step 3 returns HTTP 422 with `code:'invalid_request'`; step 2 returns HTTP 403 with `code:'authentication_rejected'`; step 4 returns HTTP 503 with `code:'v3_service_role_unavailable'`, zero Supabase/database/network call and zero nonce/authority/label/audit write. The `error` value is the route-family literal above. Step 2 includes absent/malformed/wrong bearer, missing internal-auth configuration, unknown/inactive key, role absence, stale timestamp, body-hash mismatch and invalid signature. Raw helper/config/principal details are logged only as a bounded server-side category and are never returned. An earlier step always wins a collision. The exhaustive route catalog below owns successful bodies and step-5 expected/unknown failures; no unlisted human-authority route exists in this checkpoint.

After signature validation, every human-authority route except the four blinded link routes calls `consume_internal_nonce_v3(principalId,requiredRole,nonce,timestamp)`. The function first proves the exact active database binding for `(principalId,requiredRole)` at its captured transaction timestamp and then atomically inserts the nonce plus exactly one `opportunity_rpc_audit_v3` row with subject `nonce` and disposition `consumed`; either both commit or neither does. The four link routes instead pass nonce and request timestamp directly to their one combined RPC under the atomic protocol below; they never call `consume_internal_nonce_v3` separately. Replay, stale timestamp, inactive key, absent/conflicting database role binding, wrong role, invalid signature or unknown key fails before a nonce/audit or authority/label row is written. Nonces may be deleted only after 24 hours by an authenticated maintenance job; deletion never changes an authority manifest.

Authority RPCs set approving/reviewer IDs from `callerPrincipal`; valuation expiry is exactly 30 days from its database review timestamp. The discovery, publisher, instrument, manual-alias, sector, peer-reviewer and peer-relationship authority RPCs take the exact registry-then-stream lock and append/idempotency path in `authority-supersession-contract.md` v3.2; instrument official-name alias activation/revocation is atomic with its instrument event. Every caller-bound RPC captures one database transaction timestamp and requires exactly one active `internal_principal_role_bindings_v3` row for its fixed role at that timestamp; a passed principal UUID alone is never sufficient. Every RPC rejects unknown enum/domain fields, role mismatch and a supplied actor/time. Corrections append; none updates an accepted authority/observation row.

`comparisonBaselineKey` is not a caller-selected model label. It must be a lowercase 64-hex value byte-equal to the bound complete `evaluation_input` manifest header's `comparisonContractKey`; registration rejects any mismatch. Available-run selection additionally requires that same value to equal `opportunity_runs.comparison_contract_key`. Thus one registration, evaluation manifest and consuming run share one normative comparison-contract identity.

## Blinded label isolation

The four link routes implement one atomic blinded operation boundary. They do not call `consume_internal_nonce_v3`. After server-side HMAC verification and body validation, the route makes exactly one call to `get_link_audit_assignment_v3` or `submit_link_audit_label_v3`, passing the verified principal, fixed route role, signed nonce and signed request timestamp. The function captures one database transaction timestamp, rechecks timestamp/role binding, inserts the nonce, evaluates the complete blinded state machine and writes its success audit/label when applicable in that same PostgREST transaction. Every expected failure is raised as an uncaught PostgreSQL exception, so nonce, label and audit changes from that invocation roll back together. A failed invocation therefore creates zero durable row; a nonce row left by an earlier successful invocation may cause a later replay failure but is not a write by the failed replay.

Link-audit sample identity is the composite `(sampleManifestId,sampleId)` from `storage-schema-contract.md`; `sampleId` alone is never authority. `link_audit_label_role_v3` is exactly `reviewer_1|reviewer_2|adjudicator`. `link_audit_assignment_disposition_v3` is exactly `reviewer_open_slot|reviewer_existing_label|reviewer_slots_full|adjudication_pending|adjudication_not_required|adjudicator_open|adjudicator_existing_label|adjudication_completed`. Both functions capture one transaction timestamp and apply the database role-binding check above. For every successful assignment the route serializes the returned evidence columns as exact nested object `{sourceKey,evidenceRef,reviewContext,mentionStartOffset,mentionEndOffset,normalizedToken,linkMode,engineOutcome,engineReason,engineCanonicalSymbol,reviewEvidenceHash}` in that key order; `engineCanonicalSymbol` alone may be null. It validates the stored hash before serialization, and the complete canonical HTTP success body is <=4,096 bytes.

The two assignment routes accept exactly `{sampleManifestId:string,sampleId:string}` and respectively supply `requested_role=link_reviewer|link_adjudicator`; the body cannot contain a role. `/reviewer-label` accepts exactly `{sampleManifestId,sampleId,labelRole:'reviewer_1'|'reviewer_2',canonicalSymbol:string|null,noLink:boolean}` and supplies `requested_role=link_reviewer`. `/adjudication` accepts the same shape but requires literal `labelRole:'adjudicator'` and supplies `requested_role=link_adjudicator`. Every route is POST, accepts no query, has a 4,096-byte raw-body maximum and signs its own literal canonical path. A dual-role principal therefore chooses a branch only by calling one exact signed operation.

For a request that matched one of those four literal paths, the outer precedence specializes the five-step rule above and is total: (1) non-POST, any query, wrong media type, duplicate JSON member, or a raw body over 4,096 bytes is `invalid_request`; (2) absent/malformed/wrong legacy bearer or unavailable internal-auth configuration, followed by missing/malformed signed headers, unknown key ID, inactive/expired key, required route role absent from the secret mapping, invalid timestamp/nonce grammar, timestamp outside the server 300-second window, body-hash mismatch or signature mismatch, is the single `authentication_rejected`; (3) exact body-schema/unknown-field/route-branch failure is `invalid_request`; (4) service-role client acquisition either succeeds or returns `v3_service_role_unavailable`; (5) the combined RPC applies its database precedence below. Steps 1-3 never acquire a service client; step 4 never invokes PostgreSQL. Thus transport outranks both authentication controls, authentication outranks body, body outranks client acquisition, and client acquisition outranks every nonce/sample/binding/branch/symbol or database-error fact.

`get_link_audit_assignment_v3` is total over every valid role/sample/label state. Its exact database failure precedence is: (1) `invalid_requested_role` when the typed role is not `link_reviewer|link_adjudicator`; (2a) `authentication_rejected` for request timestamp outside 300 seconds of the one database timestamp, invalid nonce grammar or nonce uniqueness conflict; (2b) `principal_role_unavailable` for a differing greatest database binding or no exact effective-active `(callerPrincipal,requestedRole)` binding; (3) `assignment_unavailable` for a missing/non-complete/hash-mismatched composite sample; (4) `principal_already_other_branch` when a reviewer caller owns the adjudicator row, or `principal_not_distinct` when an adjudicator caller owns either reviewer row. Step 2a precedes 2b when both fail. The nonce insert occurs only after checks (1)–(2b), and any later failure rolls it back. Only after all failure checks is one disposition returned and nonce plus audit committed. Publicly both step-2 database messages collapse to the same authentication envelope; database evidence retains the distinct binding identity.

For `link_reviewer`, an existing own reviewer label returns `reviewer_existing_label`, its own role/value and null reviewer-pair columns. Otherwise the first open slot in order `reviewer_1`, then `reviewer_2` returns `reviewer_open_slot` with that assigned role and every label-value column null. If both slots belong to other principals, return `reviewer_slots_full`, null assigned role and all label-value columns null. Reviewers never receive another label or adjudication. For `link_adjudicator`, an existing own adjudicator label returns `adjudicator_existing_label`, assigned role `adjudicator`, its own value and both disagreeing reviewer value pairs without reviewer IDs. With fewer than two reviewer labels, return `adjudication_pending`; with two matching labels, return `adjudication_not_required`; both have null assigned role and all label-value columns null. With two disagreeing labels and no adjudicator, return `adjudicator_open`, assigned role `adjudicator`, null own value and both reviewer value pairs without identities. With an adjudicator row owned by another principal, return `adjudication_completed`, null assigned role and all label-value columns null. The identical hash-validated `reviewEvidence` and composite sample identity are present for every successful disposition; reviewer-label nullability never changes evidence visibility.

`submit_link_audit_label_v3` locks the composite sample row and applies this exact database precedence: (1) `invalid_requested_role` when the typed role is not `link_reviewer|link_adjudicator`, then a requested-role/label-role branch mismatch is `invalid_label_role`, then the symbol/no-link XOR shape is `invalid_label_value`; (2a) request timestamp and nonce/replay failures are `authentication_rejected`; (2b) every database binding failure is `principal_role_unavailable`, with 2a winning a collision; (3) an unavailable composite sample is `assignment_unavailable`; (4) stored cross-branch identity is `principal_already_other_branch|principal_not_distinct` as above; (5) branch state; (6) a syntactically valid symbol absent from the instrument/alias manifests bound by the sample's evaluation manifest is `label_symbol_unavailable`; only then may it commit nonce, label and audit. Route/body schema failure has already terminated at the route boundary as `invalid_request`. Any failure after provisional nonce insert raises and rolls the transaction back.

Reviewer branch state is exact. If the caller already owns a reviewer row, passing the other role is `label_slot_not_assigned`; the same role/value is idempotent and a changed value is `label_conflict`. With no own row, passing anything except the first open slot (`reviewer_1`, then `reviewer_2`) is `label_slot_not_assigned`; both slots occupied is `label_slot_unavailable`. Adjudicator branch state is exact. Fewer than two reviewer labels is `reviewer_pair_incomplete`; a matching pair is `adjudication_not_required`; an adjudicator row owned by another principal is `adjudication_completed`; an existing own identical row is idempotent and a changed value is `label_conflict`. The sample lock means there is no separate implementation-selected concurrency code: a raced submission observes and reports this same ordered current state.

Transport/body validation maps to HTTP 422 and `code=invalid_request`; every legacy-bearer or signed-principal failure maps to HTTP 403 and `code=authentication_rejected`; service-client acquisition failure maps to HTTP 503 and `code=v3_service_role_unavailable`. Every expected combined-RPC failure returns no row and raises the exact `link_audit_failure_code_v3` label as PostgreSQL `MESSAGE`, with null `DETAIL/HINT`: SQLSTATE is `PT422` for `invalid_requested_role|invalid_label_role|invalid_label_value`, `PT403` for `authentication_rejected|principal_role_unavailable`, `PT404` for `assignment_unavailable`, and `PT409` for every other expected RPC code. The server catches only those SQLSTATE/message pairs and maps them respectively to HTTP `422|403|404|409`. A caught `PT403/principal_role_unavailable` is mapped to public `code=authentication_rejected`; it is never serialized or logged as public authority. All route, client-acquisition and caught-RPC failures return RFC-8785 canonical JSON with exactly keys `code,error`, where `code` is that mapped public label and `error` is literal `link_audit_request_rejected`, plus `Cache-Control: private, no-store`; no bearer, principal, key, nonce, role, binding, configuration or sample detail is added. `v3_service_role_unavailable` is a route-local pre-RPC code and is deliberately not a `link_audit_failure_code_v3` enum member. An unknown database error returns HTTP 500 with the same two-key object and `code=link_audit_internal_error`. Every logical failure has zero durable nonce, label and RPC-audit write from that invocation. Evaluation reads an agreed reviewer pair or the adjudicator row only after the terminal rule is satisfied. Public routes expose only aggregate metrics and opaque sample-manifest refs.

## Service-role fail closed

V3 imports a new server-only `getOpportunityV3ServerClient()` and never imports or calls legacy `getSupabaseServerClient()`. Its complete configuration tuple has no fallback and is exactly `(SUPABASE_URL,OPPORTUNITY_V3_SUPABASE_PROJECT_REF,SUPABASE_SERVICE_ROLE_KEY,OPPORTUNITY_V3_SERVICE_ROLE_KEY_SHA256)`. It never reads `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_KEY` or another key/URL name.

Offline acquisition validates all four values before constructing a client. Project ref is exactly 20 lowercase ASCII alphanumeric characters. `SUPABASE_URL` must parse by WHATWG URL with scheme `https`, no username/password/port/query/fragment, pathname exactly `/`, and host exactly `${projectRef}.supabase.co`; either raw empty path or `/` may normalize to that pathname. The service key is 32..4096 visible ASCII characters with no whitespace. The approved digest is 64 lowercase hex and must byte-equal lowercase SHA-256 of the exact service-key UTF-8 bytes. The digest/project-ref pair is non-secret deployment authority from a separately approved binding checkpoint that attests this exact secret as that project's service-role credential; absent approval leaves the tuple absent and V3 disabled. A key cannot claim its own role/project through token payload fields.

Missing/empty/malformed value, URL/ref mismatch, digest mismatch, forbidden fallback presence being selected, or a synchronous client-constructor exception is an offline step-4 acquisition failure. It returns the exact route-family `v3_service_role_unavailable/503` body, performs zero Supabase/database/network call and writes nothing. The constructed client uses only the validated URL/key, `persistSession=false`, `autoRefreshToken=false`, no global user authorization header, and is not exported to client bundles.

After successful acquisition, a PostgREST HTTP `401|403` before the addressed function executes means the approved credential was remotely rejected, expired or revoked. This is step 5, not acquisition, and has exactly three observable positions:

1. A blinded route has one combined RPC. Rejection attempts exactly one database HTTP call and creates zero durable nonce/label/audit write.
2. A non-blinded route rejected on `consume_internal_nonce_v3` attempts exactly one database HTTP call and creates zero durable write.
3. A non-blinded route whose nonce RPC committed and whose append RPC is then rejected attempts exactly two database HTTP calls. The already committed nonce and its one successful `consume_internal_nonce_v3` audit remain; the rejected append creates zero authority/verification/registration/append-audit write. Those two rows are the complete retained first-call effect and make retry with the same signed nonce fail closed.

All three positions return HTTP 503 with `code:'v3_service_role_unavailable'`, the matched route family's exact `error` literal and `Cache-Control: private, no-store`; the wire response does not reveal the position. Other transport, timeout, `5xx`, malformed-response or uncataloged errors map to the route-family internal-error/500 body; idempotent append/combined RPC semantics determine the durable outcome and the response never falsely claims zero call or zero write. In every collision, offline acquisition loses to transport/auth/body and wins over all database facts; remote credential rejection occurs only after acquisition and wins over any RPC state that was never reached. Static and runtime acceptance must spy offline zero-call failures, the blinded/first-call one-call-zero-write branches, and the second-call two-call retained nonce-plus-nonce-audit branch on all applicable literal routes. Review context and engine fields are emitted only in the two assignment success bodies; they are forbidden from label-write success bodies, all error bodies, server logs, generic RPC audit input preimages, public/detail serializers and non-link routes.

Every V3 table enables RLS, revokes all privileges from `anon` and `authenticated`, grants only the minimum function/table privileges to `service_role`, and exposes public data solely through bounded server serializers. The shared bearer, signed principal headers and service-role secret are never persisted in artifacts, logs or error bodies.
