# V3.16.2 Activation Window Amendment

Status: implementation repair

## RED production evidence

The reviewed V3.16.1 producer run `8d98b930-46cb-428c-619d-d3c731850808`
continued to renew its database lease during the CPU-bound `facts_refresh` stage and
durably appended 960 trading sessions, 1,315 financial facts and 1,775 price
observations. At the fixed 3,600-second local scheduler wait boundary, the installer
terminated the still-healthy one-shot owner and executed its reviewed rollback. The
last heartbeat and chunk append stopped with that termination; no prior heartbeat
loss preceded it.

This is an activation-transaction window defect, not authority to weaken leases,
make an unfinished run terminal, or expose a partial projection.

## Closed repair

- The local one-shot activation wait remains finite and increases from 3,600 to
  14,400 seconds.
- The existing launchd exit status remains the success authority. Nonzero exit or
  the new finite timeout still fails closed and restores the captured runtime and
  scheduler state.
- Database lease and heartbeat semantics are unchanged. The worker-thread heartbeat
  remains mandatory for long handlers.
- Official ingestion chunks remain immutable and cutoff-bound, so the successor run
  can resume the exact scheduled occurrence rather than fabricate or duplicate data.
- An executable regression crosses the former one-hour boundary and observes a
  successful terminal owner exit; existing nonzero and finite-timeout cases remain.

## Rollout

The repair requires fresh Requirements and Architecture PASS, an exact reviewed
source commit, protected aggregate PASS, and a new short-lived production activation
authority. Production Web alias movement remains later than two terminal producer
runs and runtime doctor PASS. No database password rotation, V3 promotion, LINE,
dispatch or automatic trading is authorized by this amendment.
