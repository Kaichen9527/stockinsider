# V3.19 release reconciliation amendment

Version: `source-led-opportunity-release-v3.19.0`

Status: `contract_frozen; one fresh Requirements review and one independent Architecture review pending`

## Purpose

V3.19 is a successor to the reviewed V3.18 tree. It does not reopen V3.18
Requirements, Architecture, exact-review or migration evidence. It closes the
remaining release-integrity delta: a short installer handoff, frozen source
acquisition, non-empty source-led research visibility, same-revision detail,
and a single durable release checkpoint without a Goal, heartbeat automation
or cron.

## Closed requirements

1. The release checkpoint advances only in this order:
   `workspace_ready`, `contract_passed`, `implementation_reviewed`,
   `runtime_staged`, `run1_terminal`, `web_deployed`, `run2_terminal`,
   `verified`, `closed`. It cannot skip an identity-bearing phase.
2. Runtime installation waits only for scheduler registration plus the first
   durable heartbeat, bounded to two minutes. A producer run owns its own
   terminal outcome; interrupted activation restores the prior owner or
   completes a new activation journal, never leaving old owners disabled.
3. A source-led candidate has exactly one non-executable research-readiness
   lane: `actionable`, `near_action`, `wait_condition` or `data_needed`.
   DecisionEnvelope remains the only action authority. A common runtime,
   manifest, calendar or source fault disables actions but preserves checksum
   valid last-good research and its navigable same-revision detail.
4. InvestAnchors and Telegram can enter the candidate path only as an
   operator-authorized, bounded structured claim with stock-context validation
   and a citation. Raw paid/member text, raw Telegram text, metadata-only
   content and unapproved OAuth responses are terminal outcomes, never thesis.
5. The completed source-sync transaction persists each bounded authorized
   document before it creates its claim shard. A successful-run cursor selects
   only documents created or changed since its last consumed high-water mark;
   it never replays the historical corpus. A same-run document is frozen once,
   while metadata-only, rejected and unchanged outcomes remain non-claim
   terminal evidence.
6. Official data may validate, enrich and reject a source-nominated symbol; it
   cannot nominate one. A bare four-digit token is rejected unless its active
   master symbol is paired with an active master name/alias or a clear stock
   context.
7. The runtime must fail closed below the reviewed free-space floor or when
   retained source-audit output exceeds its bounded capacity. Capacity
   observation does not delete evidence; any cleanup is a separately audited
   exact-target operation.
8. V3.19 migration is additive, RLS protected and has no raw source payload,
   password, credential, LINE, dispatch, automatic-trading or Promotion path.
   Evaluation governance stays `blocked/non_fabricated_elapsed_cohorts_unavailable`.

## Delta verification

- Requirements and Architecture review the V3.19 delta once each. A common
  finding receives one root repair tree; recurrence is a redesign blocker,
  never another numbered loop.
- The exact reviewed tree must pass migration rehearsal, runtime crash/lease/
  frozen retry tests, contract tests, product/runtime tests, lint, typecheck,
  build, browser accessibility/performance tests and exact-range closure review.
- Production applies only the reviewed additive migration, installs the same
  reviewed manifest, records two terminal runs, deploys the same tree to both
  existing Vercel projects, then proves nonzero SSR/API stock cards and
  same-revision Safari detail navigation. Smoke failure rolls back runtime and
  both aliases; additive database objects remain.
