# V3.16.9 official-ingestion transaction-time amendment

Status: implementation repair; fresh Requirements and Architecture pending

## Production RED baseline

Reviewed V3.16.8 run `21c5a5a4-aa32-7abf-ac99-7e5f1e54d89e` reached the
official facts barrier and durably staged 960 trading-session items, 1,315
financial facts and 1,937 price observations. The first reported-valuation
chunk then failed at `2026-08-15T20:55:38.115Z` with the typed diagnostic:

- stage/job: `facts_refresh` / `stage_barrier`;
- failure: `data_integrity_failure`, origin `persistence`;
- SQLSTATE: `PT409`;
- field: `officialIngestion.reported_valuations`, ordinal `0`;
- producer: `6c986eca0da0904b9af173e13359a457cfee0060`.

The installer rolled the runtime pointer and scheduler back to reviewed V3.16.7
`184390953048209730c22828548858c28fa3b6b7`; Web was not deployed. The database
credential is not reset or printed.

The root is a two-clock contract error. Calendar rows carry evidence
`sourceTimestamp` and `collectedAt` at or before the immutable run cutoff, but
their database `recorded_at` is the later transaction time. Price and PE apply
looked up that freshly appended parent with the public point-in-time resolver at
the earlier evidence cutoff, so it correctly returned zero rows. Price apply
silently continued and its application ledger therefore overstated successful
materialization; PE failed closed with `calendar_authority_mismatch`.

## Requirements

1. Public point-in-time readers remain unchanged: a row with
   `recorded_at > cutoff` is not visible at that cutoff.
2. Same-ingestion parent resolution uses two independent bounds: parent
   `source_timestamp` and `collected_at` must be no later than the child
   knowledge cutoff, while parent `recorded_at` must be no later than the
   current transaction cutoff.
3. The resolver selects one latest transaction head, preserves the 1,024
   revision bound, and rejects equal-head semantic conflicts. It never selects
   source evidence that was unavailable at the child knowledge cutoff.
4. Price, corporate-action and reported-valuation apply use only this private
   dependency resolver. General public valuation append and all analytical
   point-in-time reads retain the original resolver.
5. Missing instrument, calendar, price or valuation-metric dependencies are
   typed failures. A staged nonempty item cannot be recorded as applied after a
   silent `CONTINUE`.
6. The repair is additive/apply-twice-safe, privately owned, unavailable to
   `PUBLIC`, `anon`, `authenticated` and `service_role`, and appended to the
   authority-bound reviewed migration chain.
7. No LINE, dispatch, automatic trading, V3 Promotion, destructive DDL,
   credential reset or fabricated evaluation cohort is permitted.

## Architecture

```text
immutable evidence cutoff                 database transaction cutoff
          |                                          |
          v                                          v
 parent source/collection <= child cutoff   parent recorded_at <= now
          +---------------------+--------------------+
                                v
               one private dependency authority head
                                |
           +--------------------+--------------------+
           v                    v                    v
       raw price       corporate-action snapshot    PE/PB row

 public historical resolver remains recorded_at <= historical cutoff
```

The migration installs a private four-argument dependency resolver, a private
transaction-aware reported-valuation append function and an upgrade-safe
replacement for the preserved V3.15 chunk-apply base. The outer staged-chunk
hash verification, immutable application ledger, <=20-row bound, lease and
terminal conservation remain unchanged.
