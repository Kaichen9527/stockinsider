# V3.16.10 same-transaction dependency visibility amendment

Status: bounded production repair; exact review and protected Code Gate pending

## Production RED baseline

Reviewed V3.16.9 run `762daa51-3de5-71bb-d1b6-4b2d17a98833` staged 960
official trading sessions, 1,315 financial facts and the first 200 price rows,
then failed closed at price chunk ordinal 9 with typed SQLSTATE `PT409` /
`calendar_dependency_unavailable`. The reviewed installer rolled back the
runtime pointer and scheduler; Web was not deployed.

The staged calendar row was present and semantically eligible. The private
four-argument dependency resolver was declared `STABLE`, so PostgreSQL retained
the outer terminal-completion statement snapshot and could not see calendar
rows applied earlier in that same statement.

## Requirements and architecture

1. Terminal completion remains one atomic statement and applies chunk kinds in
   dependency order.
2. The private same-ingestion resolver must observe command-counter advances
   from earlier writes in that statement; it is therefore `VOLATILE`.
3. Its two-clock predicates, 1,024-row bound, latest-head selection and
   semantic-conflict rejection remain byte-for-byte unchanged.
4. Public point-in-time resolvers remain unchanged and fail closed on rows
   recorded after their historical cutoff.
5. The migration is additive, apply-twice safe, authority-bound and changes no
   grants, owners, public API, credential, runtime mode or promotion behavior.
