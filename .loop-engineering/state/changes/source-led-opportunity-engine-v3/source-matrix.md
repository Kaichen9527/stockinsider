## Independence Rules

Source-class keys are exactly: `official` (MOPS/earnings/material events), `public_research` (verified broker/research), `curated_thesis` (InvestAnchors and approved KOL/podcast), and `community` (Threads/BullTalk/PTT/approved Telegram/Instagram). Market providers have no discovery class. One source identity belongs to one class under the server allowlist version.

Discovery identity authority is additive `source_identity_authorities_v3(authorityId,sourceIdentityId,sourceKey,sourceClass,distributionIdentity,validFrom,validTo,status,approvedAt,approvingPrincipalId,recordedAt)`. `sourceIdentityId` is a required non-null stable UUID FK to a `source_entities` display row; only the ID is reused, while every mutable legacy field is non-authoritative. The authority table has a unique `(authorityId,sourceIdentityId,sourceKey)` key for the revision composite FK. Writes require a signed `source_reviewer` principal; null identity, unknown display ID and duplicate/conflicting immutable payloads fail before append. Corrections/revocations append a new authority UUID. At cutoff, first apply the discovery stream `[sourceIdentityId]` latest-event algorithm in `authority-supersession-contract.md`, including inactive/expired terminal rows. Only a selected `effective_active` event whose `sourceKey/sourceClass` is an exact static mapping is allowlist membership.

The post-supersession selected event row is `[authorityId,sourceIdentityId,sourceKey,sourceClass,distributionIdentity,validFrom,validToOrNull,status,approvedAt,approvingPrincipalId,recordedAt]`, with manifest terminal code `effective_active|revoked_or_expired`. No field in the three-column admission identity may be null. Rows order `sourceIdentityId`, then source key, valid-from, approved-at, recorded-at and authority UUID ascending. The `LIMIT 10001` sentinel is applied to these selected streams before terminal filtering; row 10001 fails `identity_manifest_overflow`. Under `manifest-storage-contract.md`, `sourceCutoff,rowCount` are the `source_identity_allowlist` header fields, `rowCount` counts all terminal selected streams, and these exact rows are its `rows` section. Consumers admit only `effective_active`; a conflicting latest event is `authority_revision_conflict`. Source revision consumers require byte-equality of all `(authorityId,sourceIdentityId,sourceKey)` fields, never authority-ID membership alone. `sourceIdentityAllowlistManifestHash` is the universal root hash; references to this domain's manifest preimage mean those header/native row values, never a second monolithic-array hash.

Priors, TTLs, connector keys, source-class mapping, verification/enrichment modes, lookbacks and the per-connector scan cap are the following exhaustive static configuration. Class rows use this exact order:

```json
[["official",1,3024000],["public_research",0.85,604800],["curated_thesis",0.7,604800],["community",0.45,259200]]
```

Each class row is `[sourceClass,sourcePrior,classTtlSeconds]`. Source rows are `[sourceKey,sourceClass,discoveryAllowed,verificationMode,marketEnrichmentMode,lookbackSeconds,scanCap]`, sorted by ASCII source key, and are exactly:

```json
[["bulltalk","community",true,"none","none",259200,1000],["earnings_call","official",true,"official_fact","fundamentals",3024000,1000],["instagram","community",true,"none","none",259200,1000],["investanchors","curated_thesis",true,"thesis_only","none",604800,1000],["mops_material_event","official",true,"official_fact","fundamentals",3024000,1000],["podcast","curated_thesis",true,"thesis_only","none",604800,1000],["ptt","community",true,"none","none",259200,1000],["public_broker_research","public_research",true,"verified_publication","none",604800,1000],["telegram","community",true,"none","none",259200,1000],["threads","community",true,"none","none",259200,1000],["youtube","curated_thesis",true,"thesis_only","none",604800,1000]]
```

The exact static preimage is `{"version":"source-funnel-v3.0","eligibilityVersion":"source-eligibility-v3.0","selectionVersion":"source-selection-v3.0","claimEvidenceStanceVersion":"claim-evidence-stance-v3.0","classRows":[...],"sourceRows":[...]}` using those arrays. `sourceFunnelPolicyHash = SHA256(UTF8(RFC8785(preimage)))` lowercase hex. Any prior, TTL, mapping, mode, lookback, cap or semantic-version change creates a new static hash; no runtime row or cutoff enters it.

`sourceFunnelPolicyHash` belongs in both final logical idempotency and `comparisonContractKey`. The point-in-time `sourceIdentityAllowlistManifestHash` belongs in final logical/source-dataset keys but not the comparison key. Consequently an identity-row change creates new run inputs while preserving comparable lineage, whereas a static funnel-policy change creates a new logical key and comparison lineage.

## Verification Authority

The server-owned `source-publisher-allowlist-v3.0` is point-in-time and hash-bound. A `publisher_verification_authorities_v3` row identifies authority ID, `publisherIdentityId`, source class, official domains/feed identity, institution identity when applicable, valid-from/to, `approvedAt`, approving principal ID, status and database-generated `recordedAt`. Writes use the exact dual-controlled `publisher_reviewer` route in `auth-principal-contract.md`; correction/revocation is a new row. At cutoff, first apply the publisher stream `[publisherIdentityId]` algorithm in `authority-supersession-contract.md`. Only its `effective_active` terminal row is usable; request payloads cannot select or override it.

The static comparison policy identity is distinct from the daily authority rows. `publisherVerificationPolicyHash = SHA256(UTF8(RFC8785({"version":"publisher-verification-policy-v3.0","publisherManifestVersion":"source-publisher-allowlist-v3.0","sourceClasses":["official","public_research","curated_thesis","community"],"eligibilityPredicateVersion":"publisher-eligibility-v3.0","canonicalContentAlgorithmVersion":"canonical-content-v3.0"})))` as lowercase hex. This policy hash changes only when verification semantics/schema change and belongs in `comparisonContractKey`, the `source_dataset-v3.3` header/root and exact source-to-enrich lineage equality; it contains no cutoff, publisher, domain, approval or validity row. Point-in-time authority changes instead change the publisher manifest and run idempotency inputs without breaking comparable daily lineage.

The selected publisher event row is `[authorityId,publisherIdentityId,sourceClass,sortedUniqueLowercaseIdnaDomains,feedIdentityOrNull,institutionIdentityOrNull,validFrom,validToOrNull,approvedAt,approvingPrincipalId,status,recordedAt]` with terminal code `effective_active|revoked_or_expired`; rows order publisher ID, valid-from, approved-at, recorded-at, source class and authority UUID. Apply `LIMIT 10001` after stream supersession and before terminal filtering; row 10001 fails `identity_manifest_overflow` before `seal_inputs` or verification. Under `manifest-storage-contract.md`, `sourceCutoff,rowCount` are the header, row count includes every terminal selected stream and all rows enter `rows`; only `effective_active` is allowlist membership. A differing latest tie fails `authority_revision_conflict`. `publisherVerificationAllowlistManifestHash` is the universal root hash. References elsewhere mean this manifest hash, never the static policy hash or a second domain hash.

A broker/research document is `verified_publication` exactly when all conditions hold: its publisher identity is an `effective_active` cutoff-valid `public_research` manifest row; its immutable complete revision was produced by `source-adapter-contract.md`; the canonical URL host exactly matches an allowed publisher domain or the connector record is signed by the allowed feed identity; source scan recomputes `contentHash` from `entity-link-contract.md` and it equals the revision record's separately stored `ingestionCanonicalContentHashV3`; publication, collection, revision `recordedAt` and publisher-authority `recordedAt` are all at/before cutoff; and institution/publisher identity is non-null. `ingestionContentRevisionSha256` remains the distinct hash of the versioned raw-field payload and is never compared byte-for-byte with normalized `contentHash`; both hashes and their algorithm versions are bound in the source manifest. An official document is verified by the analogous `effective_active` cutoff-valid `official` publisher/feed row. A social repost, screenshot, forwarded PDF, claimed target without the canonical publisher artifact, or mismatched hash is never verified even when its text is identical.

The immutable verification record is a derived source-run result and may naturally be recorded after that run's historical cutoff. It stores its database-generated `recordedAt`, source-run/source-cutoff/revision IDs, publisher allowlist manifest ID/hash, publisher/institution IDs, canonical document ID/content hash, source timestamps and an opaque evidence ref. Its authority comes only from the bound cutoff-valid revision and publisher manifest, never from backdating the result's own `recordedAt`. That record determines `verified` analyst estimates, broker targets, official/public-research source classes, formal evidence, event-starter catalysts and valuation-review evidence. Distinct institutions/publishers mean distinct cutoff-valid publisher identities; connector names alone do not establish independence.

For each persisted claim occurrence, `verificationTier` is database-derived during `source_parse_batch` completion and stored on `opportunity_source_claims`. In that one completion transaction, before normalized claim insertion, the RPC derives and byte-identically inserts or reuses the sole `source_publication_verifications_v3` record from the job-bound complete revision, source cutoff, publisher manifest and validated document/content output when the verified-publication predicate holds. It is `publisher_verified` exactly when that owning revision then has one byte-matching immutable verification row for the same source run, source cutoff, revision and bound publisher manifest, and that record's publisher source class is `official|public_research`; zero matches produces `provenance_verified`, while multiple or conflicting matches fail `data_integrity_failure` and roll back the verification record, normalized rows, result and successor. A `publisher_verified` claim copies the verification record's opaque `evidence_ref` as its `sourceRef`; a provenance-only claim copies the parser's revision-bound opaque ref. Projection and evaluation may only copy the stored tier and ref; they cannot re-query current publisher authority or infer a tier from source class.

- Two reposts of one article are one claim and one independent source.
- A podcast paraphrasing a broker note is a distinct exact claim, but an explicit citation gives both the same `evidenceRootId`, so it cannot add independent verification. Independently attributable analysis without that dependency uses its own root.
- Multiple community platforms may increase reach but cannot verify a financial fact.
- Official company evidence can verify a fact but does not by itself prove valuation attractiveness or entry timing.
