# Sector Benchmark Contract: source-led-opportunity-engine-v3

Version: `sector-benchmark-v3.1`

Sector-relative evaluation uses a point-in-time custom equal-weight benchmark for each canonical non-`unknown` sector. It never uses a source mention, free-form sector label, model output or future constituent history.

For each candidate entry session, constituents are the cutoff-valid active common stocks from the bound instrument-roster and sector-taxonomy manifests assigned to the candidate's canonical sector. The entry session, every evaluated session and every price observation must be authorized by the one cutoff-resolved composite calendar in `trading-calendar-contract.md`; weekday inference and a naked session date are invalid. Require at least five constituents and official corporate-action-adjusted TWSE/TPEx closes for at least 80% of that frozen constituent count on entry and on every evaluated session. The candidate remains in the benchmark when it is a valid constituent. Missing the minimum constituent or coverage rule makes the candidate/date unevaluable with `insufficient_sector_benchmark`; it does not substitute TAIEX or an implementation-chosen industry index.

At entry, freeze all constituents with a valid adjusted close. On each evaluated session, its qualifying set is the frozen-entry constituents having both entry and session observations. Provided that set still covers at least 80% of the frozen sector roster, each qualifying constituent receives equal session weight `1 / qualifyingSessionConstituentCount`; the benchmark return is their arithmetic mean of `adjustedClose_t / adjustedClose_entry - 1`. This explicit missing-observation renormalization is the only weight change; weights never drift with price/market capitalization and a symbol is never added after entry. Candidate `sectorRelativeReturn` is candidate close return minus benchmark close return. Candidate `sectorRelativeMfe` is the maximum over aligned sessions of candidate high-to-entry return minus that session's benchmark close return.

Entry rows are `[symbol,entrySessionAuthorityId,entryAdjustedClose,priceProviderRef,providerTimestamp,corporateActionVersion]` sorted symbol. Evaluation rows are `[sessionId,sessionAuthorityHash,sessionAuthorityId,symbol,adjustedClose,priceProviderRef,providerTimestamp]` sorted session then symbol. Exchange-specific authority IDs must be members of the hash-bound composite session. Session-conservation rows are `[sessionId,sessionAuthorityHash,frozenConstituentCount,qualifyingSessionConstituentCount,coveragePct,status]` sorted session. Under `manifest-storage-contract.md`, cutoff, canonical sector, entry session, `entrySessionAuthorityHash`, the exact covering `tradingCalendarWindowHash` and roster/taxonomy/corporate-action dependencies are the `sector_benchmark` header and those exact rows populate `entry_rows`, `evaluation_rows`, `session_conservation`. `sectorBenchmarkManifestHash` is the universal root. Session weights are derived exactly from those rows. Logical kind `sector_benchmark` is stored only in the generic manifest tables; there is no dedicated `sector_benchmark_manifests_v3` physical table. Calendar, corporate-action, roster or taxonomy corrections create a new manifest; completed label/evaluation rows are not rewritten. Preparing manifest jobs freeze the benchmark hash/version before `seal_inputs`; their ordered input manifests and final logical key bind it.
