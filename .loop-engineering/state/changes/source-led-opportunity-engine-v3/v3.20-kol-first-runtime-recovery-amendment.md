# V3.20 KOL-first runtime-recovery amendment

Version: `source-led-opportunity-release-v3.20.0`

Status: `requirements_passed; architecture_passed; exact-review pending`

## Purpose

V3.20 is a bounded successor to V3.19. It fixes one production incident and
one product-authority defect without reopening historic requirements rounds,
scanning the full Taiwan market, resetting any database password, or creating a
Goal, heartbeat, cron, LINE dispatch, automatic trade or Promotion path.

## Closed contract

1. A lost producer lease becomes a durable `failed_recoverable/lease_expired`
   terminal result only when the run, leased job, commit, worker hash and
   config hash all match the reviewed caller identity. A reaper fails closed
   when zero or more than one matching lease exists. The next reviewed worker
   may then acquire a new run; it never treats an expired run as live.
2. Candidate nomination is KOL-first. Only approved KOL transcript, Threads
   API, public Telegram, authorized InvestAnchors structured claim or
   rights-attested Research Inbox claim can nominate a symbol. Official market
   data may corroborate, value, time or veto an already nominated symbol, but
   cannot create or retain a card by itself.
3. Every source sync has exactly one terminal outcome for each approved
   `(profile, connector)` pair across Threads, Podcast, YouTube, Telegram and
   InvestAnchors. Missing OAuth is `auth_failed`; metadata-only material cannot
   form a thesis; private Telegram and member article text are never acquired.
4. Entity linking needs a valid ticker plus company/name/context evidence. A
   generic market phrase such as `新興市場 ETF` cannot link to 新興 2605.
5. V3.20 retains the 60 → 30 → 20 limits. Only the KOL-nominated population
   can enter the 60; official facts are loaded only for selected candidates.
   A missing fact produces an explicit research/data-needed state, never a
   fabricated target price or a false `avoid`.
6. A stale projection disables action authority through its health overlay but
   keeps the original immutable decision revision, dossier and last-good card
   navigable. The same `decisionRevisionId` must never describe rewritten
   decision bytes.
7. The public Radar paths remain additive at `legacy-radar-v3.20.0`; V3 stays
   precisely disabled at `/api/opportunity-v3` until separately authorized.

## Required release path

One Requirements review, one independent Architecture review, exact-commit
review, one normal protected PR, additive migration rehearsal/application, one
reviewed runtime installation, two terminal producer runs, matching prebuilt
deployments to the two existing Vercel projects, read-only API/Safari smoke and
one evidence carrier. Any smoke failure rolls runtime and both aliases back;
additive schema objects remain. Evaluation governance remains
`blocked/non_fabricated_elapsed_cohorts_unavailable`.
