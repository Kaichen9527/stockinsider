# V3.16.1 production heartbeat-resume amendment

Date: 2026-08-15
State: implementation subject

## Reproduced RED baseline

The reviewed direct PostgreSQL runtime reached production `facts_refresh` after
3,426 terminal jobs, then spent longer than the 120-second lease on bounded
official acquisition.  The job and run heartbeat remained fixed at the claim time,
the lease expired, no official ingestion chunk was written, and activation restored
the prior runtime.  The failure did not change credentials and left zero incomplete
chunks.

Two lifecycle defects shared the same lease-availability root:

1. `runWithLeaseHeartbeat` explicitly unreferenced its only heartbeat timer.  A
   provider promise whose sockets do not retain the event loop could therefore keep
   application work pending without keeping the lease timer eligible to run.
2. The durable PostgreSQL adapter exposed one pooled connection.  A slow official
   chunk write could queue its heartbeat on that same connection until after expiry.

## Closed contract

- The heartbeat timer is referenced for the entire handler lifetime and is cleared
  immediately when the handler terminates.
- The adapter has exactly two bounded connections so heartbeat work remains
  independent of the single active durable write.
- Lease loss remains fail-closed: no completion is attempted after a false or failed
  heartbeat, and activation rolls back the runtime pointer and scheduler owner.
- The Keychain database reference, database schema, authority token, immutable
  hashes, producer candidate bounds, decision rules and public API are unchanged.
- Tests must prove the long-handler heartbeat timer is referenced and cleaned up,
  and that the adapter reserves the second bounded connection.

## Release boundary

This amendment authorizes only the already approved coordinated V3.16 production
completion: fresh Requirements and Architecture review, exact-range review,
protected Code Gate, two terminal reviewed producer runs, the matching Vercel Web
release and read-only browser verification.  It does not reset the database
password, enable V3, LINE, dispatch, automatic trading or Promotion.  Evaluation
governance remains `blocked/non_fabricated_elapsed_cohorts_unavailable` until real
elapsed cohorts exist.
