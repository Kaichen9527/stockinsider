# Market Contract: source-led-opportunity-engine-v3

Version: `market-context-v3.6`

## Freshness and Completeness

- Trend and breadth: latest completed Taiwan session, valid through next Taiwan session close.
- Flow/credit and derivatives: at most two completed Taiwan sessions old.
- Global: at most two sessions old in the instrument's home market.

Provider authority is field-owned and versioned by `market-provider-v3.2`: TWSE owns TAIEX/TWSE closes, breadth, cash-flow and margin facts; TPEx owns OTC/TPEx equivalents; TAIFEX owns futures open interest, put/call and Taiwan VIX facts. FinMind is the first mirror fallback and `node-twstock` the second close-only fallback, used only when no cutoff-valid owner row exists for that exact fact/scope/session. Global input keys each bind exactly one server-allowlisted provider identity in this version. A row is cutoff-valid only when observation time, collection time and database `recorded_at` are all at/before cutoff; a session-bound row must additionally reference the exact applicable exchange member of the composite session authority selected by `trading-calendar-contract.md`. Within the selected authority tier choose greatest observation timestamp, then greatest collection timestamp, then greatest `recorded_at`, then ascending source ref; different normalized values still tied after these rules make that component missing with `provider_conflict`. A lower tier never overrides an existing owner row. `authorityDate` is caller-absent and database-derived before stream locking: it equals `sessionId` for a session-bound row, the global `providerSessionDate` below for a global row, and `(observedAt AT TIME ZONE 'Asia/Taipei')::date` for every other row. Each exact `(factKey,scopeKey,authorityDate,provider,providerIdentity)` market-observation authority stream admits at most 64 revisions: the append RPC locks that stream and probes indexed row 65 before insert; the 65th distinct immutable revision is zero-write `bound_violation`, while a semantic duplicate reuses its existing observation ID.

### Exact stock-price provider and correction authority

`priceProviderAllowlistHash` is lowercase hex `SHA256(UTF8(RFC8785(preimage)))` over exactly this JSON array. A terminal exchange row is `[exchange,rawPriceProviderTiers,corporateActionAuthority]`; every raw-price tier is an array of `[priceProvider,null]`, while corporate-action authority is `[officialProvider,orderedRequiredFeedIdentities]`. The second array member is the sole accepted adjusted-price algorithm literal. Array order, tier order, feed order and nulls are hash-significant.

```text
[
 "market-price-provider-allowlist-v3.1",
 "tw-corporate-action-v3.1",
 [
  ["TWSE",[[["twse",null]],[["finmind",null]]],["twse",["twse:twt49u:v1","twse:twtauu:v1","twse:twtb8u:v1"]]],
  ["TPEX",[[["tpex",null]],[["finmind",null]]],["tpex",["tpex:exright-cal:v1","tpex:reduction-reference:v1","tpex:change-reference:v1"]]]
 ]
]
```

Its canonical UTF-8 length is exactly 313 bytes and its required digest is `48fa54ee9f0e3a0b888ac0dc17eda8ad5bb746106a6fe4395eb50a5865e4e44e`. `price_observation_input_v3.provider` is the closed `price_provider_v3` type `twse|tpex|finmind`; no `taifex|node_twstock|global_allowlisted` value is representable. `TWSE` accepts raw-price owner `twse` then fallback `finmind`; `TPEX` accepts raw-price owner `tpex` then fallback `finmind`. Corporate actions have no mirror tier: only the tabled exchange owner and all three of its required feed identities can seal a snapshot. Every other exchange/provider/feed pairing is rejected before any price, snapshot, event or RPC-audit write. Machine ingestion has no nonce and uses the one discriminated price-authority runner route in `auth-principal-contract.md` v3.8. `corporateActionVersion` must be literal `tw-corporate-action-v3.1`. A later adjustment algorithm, provider, tier, feed or exchange mapping requires a new allowlist version/hash and compatibility checkpoint; it cannot reinterpret retained rows.

The six feed identities are compiled constants rather than caller-selected URLs. They map respectively to the official TWSE result pages `/zh/announcement/ex-right/twt49u.html`, `/zh/announcement/reduction/twtauu.html`, `/zh/announcement/change/twtb8u.html` on `www.twse.com.tw`, and the official TPEx result pages `/zh-tw/announce/market/ex/cal.html`, `/zh-tw/announce/market/reduction/reference.html`, `/zh-tw/announce/market/change/reference.html` on `www.tpex.org.tw`. The first identity in each exchange array maps only to `ex_right_dividend`, the second only to `capital_reduction`, and the third only to `par_value_change`. Each adapter projects exactly the official effective/resumption date, security code, before-action/last-trading closing price and published reference/resumption price; missing, duplicate or nonnumeric required projection fields reject that feed. For each feed, the adapter issues one HTTPS query whose from/to date is exactly `sessionId`, requests the complete CSV representation, accepts status 200 with zero redirect only, caps response bytes at 8,388,608 and rejects HTML, pagination, an unexpected schema/header, duplicate symbol, out-of-session row or caller-supplied host/path/query. The TWSE/TPEx official pages define the authoritative before-action closing/reference-price pairs for ex-right/ex-dividend, capital-reduction resumption and par-value-change resumption. A required feed returning a valid header plus zero rows is successful evidence; a transport/schema/size failure makes the whole exchange/session snapshot unavailable and cannot be interpreted as no action.

Corporate-action authority is a separate complete daily snapshot, never a field copied into a raw price row. Exact `corporate_action_snapshot_input_v3` contains the exchange/session/calendar authority, literal algorithm version, one owner provider, one `collectedAt`, and exactly three ordered feed evidence members `[feedIdentity,responseByteCount,responseSha256,parsedRowCount]`, followed by `declaredEventCount` and symbol-ascending event rows. Each event row is `[symbol,eventKind,preActionReferencePrice,postActionReferencePrice,feedIdentity,sourceRowRef]`; `eventKind` is the closed `corporate_action_kind_v3` value `ex_right_dividend|capital_reduction|par_value_change`, symbol is the exact trimmed exchange security code from the official row, pre/post are finite positive official values and the feed identity must match the kind. The database requires `sourceRowRef = SHA256(UTF8(RFC8785(["corporate-action-source-row-v3.1",exchange,sessionId,symbol,eventKind,preActionReferencePrice,postActionReferencePrice,feedIdentity])))`; it is not an opaque caller hash. The three response digests are over the received bytes before parsing. Each adapter removes byte-identical rows within its own feed before constructing the request, and `parsedRowCount` is the resulting number of valid in-session unique rows for that feed. The three parsed counts must sum exactly to `declaredEventCount`, which must equal the 0..20,000 retained event rows. A symbol may occur only once across the complete three-feed snapshot; any cross-feed symbol collision is `authority_conflict`. No instrument-class filtering is allowed, so common stocks, ETFs and other official rows all participate in completeness. The snapshot dataset hash is `SHA256(UTF8(RFC8785(["corporate-action-snapshot-v3.1",exchange,sessionId,sessionAuthorityId,corporateActionVersion,provider,collectedAt,orderedFeedEvidence,orderedEventRows])))` and is recomputed by the database, never supplied.

One `(exchange,sessionId,sessionAuthorityId,corporateActionVersion)` snapshot stream admits at most 64 immutable revisions. Its append branch takes the stream lock, reuses a byte-identical semantic duplicate, probes the indexed stream with literal `LIMIT 65`, and rejects distinct revision 65 as zero-write `PT409/bound_violation`. A consumer considers only snapshots with `collectedAt,recordedAt <= sourceCutoff`; it selects greatest `collectedAt`, then greatest `recordedAt`, then ascending snapshot UUID. Equal-time rows differing in feed evidence or event rows are `authority_conflict`; byte-identical rows collapse to the lowest UUID. There is no owner fallback. A stock's daily factor is derived only after this complete snapshot is selected: the matching event yields `postActionReferencePrice/preActionReferencePrice`; absence of its exact roster-bound symbol from that complete selected snapshot yields `none` and exact factor `1`. Absence from an unavailable, partial, conflicting or future snapshot never yields `none`.

The raw-price input contains raw OHLC only; adjusted OHLC, corporate-action fields and snapshot refs are not caller fields and are not stored as raw observation authority. For one `(stockId,exchange,sessionId,sessionAuthorityId,provider)` raw-price stream, its append branch requires `sourceTimestamp <= collectedAt <= recordedAt`, an exact calendar member, finite positive internally consistent OHLC, and finite nonnegative volume/turnover. It locks the stream, reuses a byte-identical semantic duplicate, probes with literal `LIMIT 65`, and admits at most 64 revisions. A consumer queries each exchange-allowed provider stream with `LIMIT 65`, considers only `sourceTimestamp,collectedAt,recordedAt <= sourceCutoff`, and within a tier chooses greatest source timestamp, collection timestamp and recorded time, then ascending source ref and observation UUID. Byte-identical rows except UUID collapse to the lowest UUID; authoritative-value differences still tied before UUID make that stock/session `provider_conflict`. The owner tier wins whenever it has one valid nonconflicting row; fallback is considered only when owner has none, never when owner conflicts. Calendar mismatch, future data and provider conflict never fall through to another exchange.

For a selected raw observation at completed session `S` adjusted to completed anchor session `A`, require `S <= A` and use the exact cutoff-bound consecutive calendar members in `(S,A]`, never weekdays or price presence. Resolve one complete corporate-action snapshot at every member `E` using the rules above. At most 252 intervening members are representable; a required 253rd is `bound_violation`. The `technical_history_reference` chunk design in `factor-correctness-amendment.md` keeps every one of its block-local adjusted tuples within this same bound. Define `adjustmentFactor(S,A)` as the ordered finite product of the stock's database-derived daily factor for each selected snapshot, with the empty product exactly `1`; any missing/conflicting snapshot, symbol/roster mismatch or non-positive/non-finite intermediate result makes adjusted price unavailable. Trusted runner code derives `adjustedOpen|High|Low|Close = rawOpen|High|Low|Close * adjustmentFactor(S,A)` without rounding before the owning contract's final display rule. It cannot accept or persist a caller-adjusted value.

Every adjusted price evidence tuple is exactly `["adjusted-price-evidence-v3.1",anchorSession,rawObservationId,sourceRef,rawSessionAuthorityId,rawOpen,rawHigh,rawLow,rawClose,orderedActionDays,adjustmentFactor,adjustedOpen,adjustedHigh,adjustedLow,adjustedClose]`. Each `orderedActionDays` member is `[effectiveSession,sessionAuthorityId,snapshotId,snapshotDatasetHash,eventOrNull,dailyAdjustmentFactor]` in ascending session order, where `eventOrNull` is either null or the exact `[eventKind,preActionReferencePrice,postActionReferencePrice,feedIdentity,sourceRowRef]`. Thus a factor-one day still binds the complete snapshot proving no listed action. The tuple itself, not only an opaque digest, enters the consuming manifest's native evidence row; its lowercase SHA-256 is the public/internal price ref. Every factor, sector, mover, sector-benchmark, outcome and evaluation input that consumes a price ref binds this tuple and `priceProviderAllowlistHash` directly in its manifest header or transitively through an exact bound input manifest. The deployed `priceProviderAllowlistHash` is also a static run-identity member. No request, environment variable, stored adjusted column, incomplete event response or current unbound provider preference may select price authority.

The three `stooq:*` strings are the complete V3 global provider identities, not display names or request-supplied values. The trusted global adapter maps each identity to its one compiled HTTPS host/path/symbol configuration; redirects, a different host, symbol or interval, and caller-provided URLs are forbidden and make the component unavailable. `market_observation_input_v3.provider_identity` and the stored `provider_identity` must equal the selected concrete identity for `global_allowlisted` and must be null for every other provider. The migration and runtime embed the canonical preimage and its digest as database/code-owned constants; startup and migration acceptance recompute both and fail closed on disagreement.

`taiex_close` and `otc_close` are session observations, never already-computed trend scores. Their `sessionId`, exchange-specific `sessionAuthorityId` and `observedAt` must respectively equal the selected composite session date, its TWSE/TPEx member and that member's official close instant. For each index, freeze the newest exact 60 completed composite sessions at/before `sourceCutoff`; resolve one close independently per session with the tier/tie/cutoff rules above. `close` is session ordinal 0, `MA20` is the arithmetic mean of ordinals 0..19 and `MA60` the arithmetic mean of ordinals 0..59, using positive finite closes and no rounding before the final public two-decimal rule. A missing/conflicting/future/stale member, fewer than 60 completed sessions, non-positive close or non-contiguous authority window emits the applicable `provider_conflict|future_observation|stale_observation|insufficient_history|missing_observation|non_finite_value|non_positive_denominator` exclusion; no shorter mean, weekday fill or current-provider series may substitute. The market-reference manifest binds the exact covering `tradingCalendarWindowHash` and the 60 selected close source refs, so `taiex_close/ma20/ma60` and `otc_close/ma20/ma60` are independently reproducible from stored observations.

Raw breadth and cash/margin observations use the exchange-specific `TWSE_ACTIVE_COMMON` or `TPEX_ACTIVE_COMMON` scope above; `TW_ACTIVE_COMMON` is output-only and is rejected on `append_market_observation_v3`. Resolve each exchange component independently. An `above_ma20|above_ma60` row alone has non-null `breadthNumeratorCount,breadthObservedCount,breadthEligibleCount,breadthRosterManifestId,breadthRosterManifestHash`; all other facts require those five members null. The referenced manifest must be terminal complete `instrument_roster/tw-instrument-roster-v3.0` at the observation cutoff, the hash must equal its universal root, and the exchange-specific eligible count must equal its cutoff-valid `effective_active/common_stock` rows. Counts are exact integers `0 <= numerator <= observed <= eligible <= 20000`; `value = roundHalfAwayFromZero(100*numerator/observed,2)` with observed >0. The breadth adapter derives numerator/observed from the same official adjusted-close window and bound roster—never a caller population—and the append RPC rechecks the count/hash/value constraints before write.

For `active_common_above_ma20_pct` and `active_common_above_ma60_pct`, both exchange rows must reference the same roster manifest. Combine `numeratorTotal=twseNumerator+tpexNumerator`, `observedTotal=twseObserved+tpexObserved` and `eligibleTotal=twseEligible+tpexEligible`; require both exchange components, `observedTotal>=500`, `eligibleTotal>0` and `observedTotal/eligibleTotal>=0.80`, then derive `100*numeratorTotal/observedTotal` with the same rounding. This observed-count weighting is the only allowed breadth percentage. For `foreign_cash_net_5d`, `investment_trust_net_5d` and `aggregate_margin_balance_change_5d`, sum the two selected exchange values. The derived source ref is lowercase hex `SHA256(UTF8(RFC8785(["market-composite-source-v3.1",factKey,rosterManifestHashOrNull,[["TWSE",provider,concreteIdentityOrNull,sourceRef,observedAt,collectedAt,recordedAt,numeratorOrNull,observedOrNull,eligibleOrNull],["TPEX",provider,concreteIdentityOrNull,sourceRef,observedAt,collectedAt,recordedAt,numeratorOrNull,observedOrNull,eligibleOrNull]]])))`; its `observedAt` is the earlier component time and its `authorityTier` is the weaker selected tier (`owner` before `finmind_mirror`). Missing/conflicting either exchange component or a roster/count/value mismatch makes the combined input missing with that component's first-match reason. This exact derivation is the only way an included market-reference row may use scope `TW_ACTIVE_COMMON`.

The provider/field allowlist hash and `tradingCalendarWindowHash` are frozen into market/reference manifests and all three run-identity preimages.

TAIFEX freshness is measured against the same cutoff-bound completed Taiwan composite sessions as the run: an observation is no older than the close of the second completed session preceding the applicable latest close. Global `providerSessionDate` is database-derived and caller-absent: `SOX|NASDAQ` use `(observedAt AT TIME ZONE 'America/New_York')::date`, while `USD_TWD` uses `(observedAt AT TIME ZONE 'UTC')::date`; every non-global row stores null. For global rows `authorityDate=providerSessionDate`, so the common stream cap above permits at most 64 revisions for one provider identity and home-market date after semantic duplicate collapse.

Each global identity queries raw rows in `(providerSessionDate DESC,recordedAt DESC,observationId ASC)` order through the matching partial index with literal `LIMIT 193`. Because each date has at most 64 revisions, rows 1..192 contain every revision for the greatest three distinct dates; row 193, when present, is only the fourth-date sentinel and is never selectable. Resolve each of those greatest three dates with the provider tie rule, then choose only from the greatest two resolved dates. The selected observation is fresh when `cutoff-observedAt <= interval '96 hours'`; exactly 96 hours is fresh, any positive epsilon older is stale, and a future observation is rejected earlier. A third date proves the relevant-session boundary; a fourth date, missing civil date, Taiwan weekday/session or another provider can never fill or reorder it. Fewer than two dates do not synthesize a session. Acceptance freezes zero through four dates, 0/1/64/65 same-date revisions, equal/differing ties and 96-hours-minus/equal/plus boundaries under an indexed <=193-row plan.

Core completeness requires trend, breadth and at least one of flow or derivatives. Trend requires both exact 60-session index windows. Breadth requires the count/hash equality and combined `observedTotal/eligibleTotal>=0.80` plus `observedTotal>=500` rules above against the bound official active TWSE/TPEx common-stock roster. Otherwise regime is exactly `unknown`, regardless of composite, seed coverage or a provider-supplied percentage without its count authority.

## Per-symbol institutional and credit authority

V3 chip factors read only `opportunity_stock_flow_observations_v3`; legacy `stock_signals.chip_metrics` is never a V3 point-in-time authority. The closed facts are `foreign_net_twd`, `trust_net_twd`, `margin_financing_balance_twd`, and `sbl_short_balance_shares`. Every row binds one official completed exchange session authority, stock/exchange, owner-or-FinMind tier, source/collection/database timestamps, source ref and provider revision. TWSE or TPEx is owner for its exchange and FinMind is selected only when no cutoff-valid owner row exists for that exact fact/session. Different normalized values still tied after provider, source timestamp, collection timestamp, database timestamp and source-ref ordering make that component unavailable.

For the latest six exact completed Taiwan sessions at/before cutoff, require foreign/trust TWD observations for sessions 1..5 and margin/SBL balances for sessions 1..6. `turnover_5d` is the positive sum of the same stock's official cutoff-valid session turnover for sessions 1..5. Derive the two net-flow numerators as five-session TWD sums, financing as session-1 balance minus session-6 balance, and SBL as `(session-1 shares - session-6 shares) * adjustedClose_session1`. Each divides by `turnover_5d`; missing any required session/fact, a calendar mismatch, provider conflict, non-finite value or non-positive turnover yields the corresponding excluded factor and never an older fill.

- `candidate_factor`: `sector_excess_return_5d`, `sector_excess_return_20d`, `volume_ratio_20d`, `ma20_slope_5d`, `foreign_net_5d_over_turnover_5d`, `trust_net_5d_over_turnover_5d`, `margin_balance_change_5d_over_turnover_5d`, `sbl_short_balance_change_5d_over_turnover_5d`, `monthly_revenue_yoy`, `revenue_yoy_acceleration_3m`, `quarterly_eps_yoy`, `operating_margin_yoy_delta`, `avg_turnover_20d`, `zero_volume_sessions_20d`, in that order;

An included row is exactly `[inputFamily,inputKey,scopeKey,symbolOrNull,valueKind,finiteValueOrNull,opaqueRefOrNull,observedAtOrNull,sourceRefOrNull,authorityTierOrNull,dependencyManifestHashOrNull]`. `valueKind` is `number` for the first three families and requires one finite numeric value plus null opaque ref; it is `manifest_ref` for `dependency_manifest` and requires a complete generic manifest's opaque ref plus its lowercase universal-root hash, with the numeric/observation/source/authority fields null. ## Group Scores

For an input observed at session/date `t`, historical z-scores first freeze at most the newest 512 applicable authority dates strictly before `t` and at/before `sourceCutoff`. Session-bound Taiwan facts use the exact prior 512 completed composite sessions from the bound calendar window. A non-session or global fact derives its candidate dates by querying each concrete allowed provider identity independently through `(fact_key,scope_key,provider,provider_identity,authority_date DESC,recorded_at DESC,observation_id)`, unioning those bounded streams and retaining the greatest 512 distinct authority dates. For every concrete provider stream in either class, the raw observation query is constrained to that newest-date boundary and has literal `LIMIT 32769 = 512*64+1`; rows 1..32,768 necessarily contain every revision of the greatest 512 dates, while row 32,769, when present, is only older-date sentinel evidence and is never resolved or selectable. The existence of older retained dates is valid and never makes the current computation fail. Resolve every roster date under the provider/tie rules. From this fixed roster use the most recent at most 252 available normalized observations; conflicted, missing, stale or non-finite dates remain typed unavailable and never trigger an older-than-512 fill. Require at least 60 available observations. Let `n` be history size, population mean `mu=sum(x_i)/n`, and population deviation `sigma=sqrt(sum((x_i-mu)^2)/n)`. If `sigma>0`, `z=(x_t-mu)/sigma`; if `sigma=0`, z is 0 when `x_t=mu`, +10 when greater and -10 when lower. `ZSCORE_TO_100(z) = clamp(50 + 15*z, 0, 100)`. No current-observation membership, sample-deviation, scan beyond the raw sentinel or implementation-selected zero-variance rule is permitted. Catalog and `EXPLAIN (FORMAT JSON)` acceptance must prove the matching history index and the 32,768/32,769 raw boundary independently of the 60/252 output counts.

```text
indexTrend(index) = 50 * I(close >= MA20) + 50 * I(close >= MA60)
trend = mean(TAIEX trend, OTC trend)

breadth = 0.50 * pct_active_stocks_above_MA20
        + 0.50 * pct_active_stocks_above_MA60

flow = mean(
  ZSCORE_TO_100(foreign_cash_net_5d),
  ZSCORE_TO_100(investment_trust_net_5d),
  ZSCORE_TO_100(-aggregate_margin_balance_change_5d)
)

derivatives = mean(
  ZSCORE_TO_100(foreign_index_futures_net_oi),
  ZSCORE_TO_100(-put_call_ratio),
```

Unavailable subinputs are omitted from a group mean; each group needs at least one input except trend, which requires both TAIEX and OTC, and breadth, which requires both breadth percentages.

`groupEvidence.reason` is one closed summary reason even when the group retains a score from other inputs. Select it by first match: any chosen-tier tie conflict -> `provider_conflict`; otherwise any stale required/omitted input -> `stale_input`; otherwise breadth below its coverage rule -> `insufficient_breadth_coverage`; otherwise when the group has a missing input and no earlier cause use respectively `missing_trend`, `missing_breadth`, `missing_flow`, `missing_derivatives`, or `missing_global`; otherwise `null`. Group `status` is `fresh` when a fresh score is computable, else `stale` when stale evidence is the first reason, else `missing`. Individual input status/ref/value still exposes which inputs were used or omitted. `missingGroups` contains exactly score-null groups in canonical group order, independent of the single-reason precedence.

## Composite and Regime

Weights are trend 30, breadth 20, flow 20, derivatives 15 and global 15. The composite renormalizes across available fresh groups only after core completeness passes.

Precedence:

1. Core incomplete -> `unknown`, cap 15%, composite `null`.
2. Trend <25 -> `risk_off`, cap 0%, override `trend_below_25`; otherwise breadth <25 -> `risk_off`, cap 0%, override `breadth_below_25`.
3. Composite <35 -> `risk_off`, cap 0%.
4. Composite <65 -> `selective`, cap 35%.
5. Otherwise -> `risk_on`, cap 60%.

Every input is persisted with its normalized value, provider/source ref, observed-at timestamp and freshness outcome. Every result serializes the exact `MarketContextV3.groupEvidence` shape in `data-contract.md`, plus missing groups, override reason and composite. Fixed-seed coverage is diagnostics only and cannot supply a group.

## Mover-audit price authority

`mover_price_reference` version `mover-audit-price-v3.3` is the full-roster terminal price authority required by the after-close audit; it performs no deep research. The server resolves the bounded calendar once at `sourceCutoff` and freezes the five-most-recent official completed Taiwan sessions; a manifest's `auditedSession` and `auditedSessionAuthorityHash` are the member at its zero-based descending ordinal and `previousSession` plus `previousSessionAuthorityHash` are that member's immediately preceding completed session. Every planned root binds the same `recentSessionPlanHash`. Starting from every symbol in the bound cutoff-valid active TWSE/TPEx common-stock roster, emit exactly one terminal row. An included row is `[symbol,stockId,auditedSession,auditedSessionAuthorityHash,previousSession,previousSessionAuthorityHash,endSessionAuthorityId,previousSessionAuthorityId,endAdjustedClose,previousAdjustedClose,turnoverTwd,endPriceEvidence,previousPriceEvidence,endPriceRef,previousPriceRef,endSourceTimestamp,previousSourceTimestamp,corporateActionVersion]`, where both evidence members are the exact `adjusted-price-evidence-v3.1` tuples above using `auditedSession` as anchor. The two observation authority IDs must be the exchange-specific members of the two bound composite sessions. Include only when both raw closes, every required complete corporate-action snapshot and turnover are cutoff-visible/fresh/finite, previous close is positive and turnover is at least `20000000` TWD. Included rows sort symbol ascending. Otherwise emit `[symbol,stockId,exclusionReason,auditedSessionOrNull,auditedSessionAuthorityHashOrNull,previousSessionOrNull,previousSessionAuthorityHashOrNull,endPriceRefOrNull,previousPriceRefOrNull]`, sorted reason order then symbol, using first-match order `calendar_authority_mismatch`, `provider_conflict`, `future_observation`, `missing_current_close`, `missing_previous_close`, `missing_corporate_action_snapshot`, `missing_turnover`, `non_finite_value`, `non_positive_previous_close`, `turnover_below_20000000`.

The sole conservation row is `[rosterCount,includedCount,excludedCount,exclusionReasonCounts]`, every reason including zero, with `rosterCount=includedCount+excludedCount` and equality to the bound roster header. Duplicate symbols, different corporate-action versions, a non-adjacent session, a 20,001st roster symbol or any conservation mismatch fails before completion. The universal root is `moverPriceReferenceManifestHash`. `eligibleUniverseCount` equals its included count; the Top-20 snapshot computes return from only those rows, orders return descending, turnover descending, symbol ascending, and stores the exact manifest ID/hash.

One enrich run requires at least one completed Taiwan session and builds this kind for exactly the most recent one through five sessions in session-descending input-ordinal order; zero available sessions fails `provider_unavailable` before any mover header. Root completion is the sole audit-creation event and follows `job-graph-contract.md`: every root derives/reuses one deterministic immutable audit from that price root plus the enrich run's exact upstream `source_dataset` and atomically stores its header/ranks. Ordinal zero alone binds `selected_mover_audit_id`; after the final planned root the transaction creates the dependent market-reference header bound to ordinal zero. Pending and matured observations for one session are separate append-only snapshots at different cutoffs; because that session remains in the five-session plan, it receives a matured snapshot after 72 hours even when newer sessions exist. Neither status nor symbols are updated. A mover audit's `price_manifest_id` and `source_dataset_manifest_id` must reference terminal complete exact-version roots with matching cutoff/upstream/session/session-authority/recent-plan/roster/corporate-action identities. Enrich seal binds the selected audit ID plus every ordered mover root; a calendar correction therefore creates a different root and final logical key rather than mutating a published snapshot.
