# Point-in-Time Authority Supersession Contract: source-led-opportunity-engine-v3

Version: `authority-supersession-v3.2`

This is the sole correction/revocation algorithm for mutable V3 authority families. Authority history remains append-only: a correction, suspension, revocation or reactivation appends a new UUID row and never updates/deletes an older row. Domain contracts own payload validation and manifest tuples; this contract owns which latest authority event is effective at cutoff C. Filtering to `active` before this algorithm is forbidden.

## Closed family catalog

| Family | Stream identity key | Revision ID | Authority time required at/before C | Terminal-active predicate | Post-collapse stream bound |
|---|---|---|---|---|---:|
| discovery identity | `[sourceIdentityId]`, required non-null | `authorityId` | `approvedAt` | `status=active` and static source-key/class mapping valid | 10,000 |
| publisher verification | `[publisherIdentityId]` | `authorityId` | `approvedAt` | `status=active` | 10,000 |
| instrument roster | `[stockId]` | `instrumentAuthorityId` | `sourceTimestamp` | `listingStatus=active` | 20,000 |
| stock alias | `[stockId,normalizedAlias,source]` | `aliasAuthorityId` | `sourceTimestamp` and `approvedAt` | `status=active` | 100,000 |
| sector assignment | `[stockId,market]` | `assignmentAuthorityId` | `sourceTimestamp` | `status=active` | 20,000 |
| peer reviewer | `[reviewerPrincipalId]` | `reviewerAuthorityId` | `approvedAt` | `status=active` | 1,000 |
| peer relationship | `[supplierStockId,customerStockId,"supply_chain"]` | `relationshipAuthorityId` | `sourceTimestamp` and `approvedAt` | `status=active` | 100,000 |

Independently of the post-collapse family bound, each exact stream identity in this table admits at most 64 immutable authority events across its full retained history, and the immutable `opportunity_authority_stream_registry_v3` admits at most that family's tabled bound of stream keys across its lifetime. Every family append RPC takes the family-wide registry advisory lock and then the stream advisory lock. If the key is new, it probes the registry's `(family,streamKeyHash,streamKeyCanonical)` index in ASCII hash/canonical order with literal `LIMIT bound+1` before atomically inserting the registry row and first event; a bound+1 key is `PT409/bound_violation`. It then collapses a byte-identical semantic duplicate to its existing retained UUID and executes the stream-leading index probe in `(recorded_at DESC,revision UUID ASC)` order with literal `LIMIT 65` before inserting. Rows 1..64 are the complete permitted history; observing or attempting a 65th distinct payload is `PT409/bound_violation`. Either bound failure writes no registry/event/append-audit row. A human route whose standalone nonce call already succeeded retains both that nonce and its successful nonce-audit row; runner ingestion has no nonce, exactly as `auth-principal-contract.md` v3.8 requires. These database-enforced lifetime bounds are not selector truncation and cannot be reset by status changes, valid-time changes, reactivation or a new caller nonce.

`source` for alias identity is exactly `official_roster_seed|manual_review`. An official name change that removes an old normalized alias therefore appends an `inactive` event for the old alias stream and, when eligible, an `active` event for the new alias stream in the same instrument RPC transaction. A changed discovery source key/class supersedes by `sourceIdentityId`; a changed publisher class/domain supersedes by `publisherIdentityId`; neither creates a second live stream. An edge endpoint change requires one inactive event for the old peer stream and one active event for the new stream. Request handlers never infer either event.

## Exact cutoff algorithm

For one family and cutoff C:

1. Enumerate every immutable registry key for the family in `(streamKeyHash,streamKeyCanonical)` order through the registry index with literal `LIMIT bound+1` **before** any `recordedAt`, `validFrom`, authority-time, status, expiry or other eligibility filter. Observing bound+1 is `identity_manifest_overflow` (`roster_volume_exceeded` for instrument/sector), never a discarded cutoff-ineligible key. For each of the at-most-bound registered keys, query its exact event stream through the stream-leading index with literal `LIMIT 65`; row 65 is integrity failure. Only inside that finite result filter events to `recordedAt <= C`, `validFrom <= C`, and every family authority time in the table above `<= C`. Status/listing status and `validTo` do **not** participate yet. A registered key with no cutoff-eligible event produces no manifest terminal row, but future-only or future-valid populations have already been bounded and cannot hide behind a post-filter sentinel.
2. For each stream key with at least one cutoff-eligible event select the greatest `recordedAt`. If multiple rows share that timestamp, compare the RFC-8785 canonical payload of every authoritative column except revision ID and `recordedAt`. Byte-equal rows collapse to the lexicographically lowest lowercase UUID. Differing payloads fail the whole applicable manifest/run as `authority_revision_conflict`; no status or UUID tie-break hides the conflict.
3. Order the one selected event per stream by the domain manifest order with stream key and revision UUID as final total tie-breaks. Apply the family `LIMIT bound+1` sentinel to these selected events **before** status/expiry filtering. Observing the sentinel fails `identity_manifest_overflow` (instrument/sector roster overflow remains `roster_volume_exceeded`) and never truncates an inactive tail.
4. Classify every selected event once. It is `effective_active` only when the terminal-active predicate holds and `C < validTo` or `validTo` is null. It is otherwise `revoked_or_expired`. No older event is revived. For the six single-section authority manifests (discovery, publisher, instrument, alias, taxonomy and peer reviewer), every selected event enters the existing `rows` section with its actual status/listing status and manifest-row `terminalCode=effective_active|revoked_or_expired`; only `effective_active` rows are consumer membership. Thus the universal root binds the exact revocation event rather than merely its absence. Peer relationships enter the existing selected/excluded classification after supersession and use the complete first-match exclusion precedence in `requirements.md`; inactive/expired latest events therefore cannot become selected even when an earlier reason wins. In every family, active plus revoked/expired terminal rows equals the post-collapse selected-stream count.
5. Domain-wide uniqueness is checked after active selection: discovery static mapping and one-class rules, publisher identity rules, instrument symbol/exchange rules, cross-stock alias ambiguity behavior, one sector per stock/market and peer constraints remain fail-closed. A reactivation is simply a later active event in the same stream and becomes visible only at/after both its authority times and `validFrom`.

The exact boundary is inclusive for `recordedAt`, authority times and `validFrom`, exclusive for `validTo`. Thus an inactive event recorded/approved/valid from C is already the selected revocation at C; the previous active row is visible at C−1 second but cannot reappear at C or C+1 second. A correction learned after C cannot rewrite C even with backdated business fields.

All seven append RPCs lock family registry then stream key before inserting and reject a supplied `recordedAt`. A request may append an event only for its role-authorized family. An exact canonical duplicate already present in that stream is idempotent and returns the retained UUID/time; a distinct canonical payload appends a new correction/revocation/reactivation event only while both the registry bound and indexed `LIMIT 65` stream probe pass. On human routes, replay fails earlier in `consume_internal_nonce_v3` and never reaches the append RPC; on the two runner-ingested instrument/sector routes no nonce is accepted or created. Registry and stream indexes bound one family to at most `bound*64` raw events even when every event is future-valid or otherwise cutoff-ineligible. Migration catalog and `EXPLAIN (FORMAT JSON)` acceptance must prove the registry shape, family-wide lock serialization, all seven stream-leading index shapes, global bound/bound+1, 64/65, duplicate reuse and zero registry/authority/append-audit write on bound failure. A human second-call failure may retain only the earlier nonce plus its nonce audit; machine ingestion retains neither. A sequential authority-history or cutoff-ineligible distinct-key scan is a contract failure.

`internal_principal_role_bindings_v3`, source document revisions, valuation verifications and assistive-artifact registrations retain their separately closed latest-row algorithms; they are not silently reinterpreted as one of these seven families.
