# Instrument Roster Contract: source-led-opportunity-engine-v3

Version: `tw-instrument-roster-v3.0`

Existing `stocks` is a foreign-key/display projection and is not eligibility authority. Additive `stock_instruments_v3` stores `(instrument_authority_id, stock_id, symbol, exchange, instrument_type, listing_status, official_legal_name, official_short_name, official_name, provider, source_timestamp, valid_from, valid_to, roster_version, recorded_at)`. Legal and short names are the two exact canonical RPC inputs. Legal name is 2..120 Unicode code points; short name is null or 2..40. `official_name` is database-generated as the short name when present, otherwise the legal name only when it is at most 40, otherwise null. The roster native row and every public `chineseName` use that nullable generated value; neither implementation nor a later `stocks.name` value may choose a mapping. A legal/short input seeds an official alias only when its original and normalized lengths are both 2..40; equal normalized names seed once. A 41..120-code-point legal name is retained without truncation but seeds no alias and projects null unless an eligible short name exists; 121 fails ingestion. `recorded_at` is database-generated and caller-immutable. Allowed exchange is `TWSE|TPEX`.

At cutoff, apply the instrument stream `[stockId]` algorithm in `authority-supersession-contract.md` before testing listing state/expiry. An `effective_active` row additionally requires `instrument_type=common_stock` for candidate eligibility; non-common types remain manifest authority but not candidates. A later suspended/delisted row revokes the old active row instead of being filtered away, and a later active row reactivates it. A row learned after the cutoff is unavailable to that historical run even when its business-validity interval begins earlier. The instrument RPC holds the stream lock and atomically appends official-alias events: an eligible new legal/short normalized alias receives `active`; each formerly effective official alias absent from the new name set, or every former official alias when the listing becomes non-active, receives `inactive`. Manual aliases are a separate stream and are never silently revoked by a roster-name change.

Rows come only from allowlisted official TWSE/TPEx listing-roster ingestion by the fixed runner principal in `auth-principal-contract.md`. ETF, ETN, warrant, preferred share, depositary receipt, bond and other instrument types remain ineligible/unsupported. Conflicting cutoff-valid rows fail roster integrity.

The cutoff-valid manifest contains at most 20,000 instruments across all types. Exceeding that bound fails closed with `roster_volume_exceeded`; it is never truncated. This fixed bound is also the maximum public peer-sample count.

Each post-supersession roster row is `[instrumentAuthorityId,stockId,symbol,exchange,instrumentType,listingStatus,officialNameOrNull,provider,sourceTimestamp,validFrom,validToOrNull,recordedAt]` with manifest terminal code `effective_active|revoked_or_expired`, sorted stock ID, then exchange, symbol, valid-from, source timestamp, recorded-at, provider and authority UUID. The 20,001st selected stream fails `roster_volume_exceeded` before terminal filtering. Under `manifest-storage-contract.md`, `rosterVersion,sourceCutoff,rowCount` are the `instrument_roster` header fields, row count includes every selected terminal stream, and these exact rows are its `rows` section. Consumers admit only `effective_active`; candidate membership then additionally requires `common_stock`. Every run binds `instrumentRosterManifestHash` to that universal root hash, with no second monolithic roster hash. Eligible official names seed new approved alias rows whose `recorded_at` is their own database insertion time; they inherit roster business timestamps but never backdate knowledge time. A correction/revocation creates a new manifest hash; history is not overwritten and a latest differing tie is `authority_revision_conflict`.
