# V3.18 source-led research dossier and actionability amendment

Version: `source-led-opportunity-research-dossier-v3.18.0`

Status: `contract_frozen; single fresh Requirements review pending`

## Problem statement

The V3.17 compatibility subject can render a source-linked, stale research
snapshot, but it still loses a candidate whenever an otherwise successful
source run has no new document.  It also keeps a narrow snapshot beside the
full immutable analysis payload, which makes a card's detail look empty even
when its own revision contains valuation, fundamental and technical evidence.
Those are visibility and provenance defects; they must not be solved by
inventing a buy action or by using all-market screening to nominate stocks.

## Frozen V3.18 contract

1. An approved, entity-linked source document nominates a candidate.  Official
   TWSE, TPEx and MOPS data may validate, enrich and reject it, but may not
   nominate it.  Paid InvestAnchors text and Telegram content remain outside
   acquisition.  An operator-authored Research Inbox note with an explicit
   rights attestation is the only later path for those private materials.
2. `CandidateLedgerV318` retains an entity-linked candidate for at most twenty
   completed source sessions after its last observation.  `no_new_items`, an
   OAuth outage and a provider outage retain the last-good candidate with a
   typed reason; they never mean that the market has zero research.  Retention
   ends only after the bounded session counter expires or a typed integrity
   conflict occurs.
3. `DecisionEnvelope` is still the sole action authority.  V3.18 introduces
   non-executable `ResearchReadinessEnvelope` (`actionable`, `near_action`,
   `waiting`, `data_needed`) solely for visibility and lane placement.  It may
   not convert an unavailable decision into buy, accumulate or
   research_starter.
4. Every visible card has one `decisionRevisionId`.  Its compact card contains
   only the price, formal/relative valuation band, trigger and invalidation;
   the same revision's `ResearchDossierV318` holds the complete supplied
   valuation method/bridge/scenarios, fundamentals, technical state, thesis,
   risks, citations, data dates and exact blockers.  Missing data are named as
   missing, not rendered as a negative investment conclusion.
5. A global integrity/identity/checksum conflict may fail closed.  A
   per-symbol missing fact, unavailable transcript or incomplete bridge may
   only downgrade that card to `data_needed` or `waiting`; it cannot blank
   unrelated last-good research.

## Explicit non-goals and authority

V3.18 does not set a daily buy quota, reset a database password, ingest paid
or Telegram text, enable automatic trading, LINE, dispatch or Promotion.  A
third-party OAuth failure is recorded as `auth_failed`; it is not disguised as
source success.  Production schema changes remain additive and require the
reviewed migration CLI from the exact release tree.

## Acceptance additions

- A no-new or unavailable source session preserves a cited card for session
  1 through 20, records `retained`, and exits it only at session 21.
- A retained card has the same material evidence hash and never becomes a
  newly promoted candidate merely because it was re-evaluated.
- One fixture reaches formal `buy`; one reaches `research_starter`; missing
  information reaches `data_needed` rather than `avoid`.
- The landing card exposes no more than six values.  The detail API and page
  expose only the dossier belonging to that exact revision.
- Light and dark primary CTAs meet 4.5:1 contrast and source/research/detail
  links remain keyboard reachable.

## Gate discipline

This amendment receives one fresh Requirements review and one independent
Architecture review after the contract and tests are frozen.  A same-root
finding is repaired once in the successor tree; recurrence triggers a root
redesign, not a numbered-review loop.  Exact review, protected Code Gate,
runtime rehearsal and production release evidence are new V3.18 evidence;
historical V3.16/V3.17 evidence is context only.
