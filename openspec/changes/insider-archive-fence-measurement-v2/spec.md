## 2. Required authority model and proposed ABA coverage

A future controlled archive acquisition must run inside one trusted DB transaction: resolve exact enabled backend/principal/release from authenticated server context, obtain a fresh server-generated lease owner, acquire the actual production-data-plane lease, lock and verify its live row, then register an archive-only binding/attempt. A request may select a snapshot; it cannot choose a trusted backend, principal, lease owner, generation, verified hash or receipt. Do not adopt an arbitrary existing live lease just because the caller can name its UUID. The deployed route must be able to supply this context without mutable global client headers leaking across requests.

Proposed private ledger identities are separate from legacy lease fields:

- Permanent operation ID and exact completed snapshot/raw/parser/rights binding.
- New non-reusable archive binding UUID and DB-maintained monotonic attempt generation for that operation; overflow refuses. Owner UUIDs generated for controlled acquisitions must never be reused in this ledger.
- Authenticated backend/principal/release plus exact lease key/owner and acquired_at/expires_at observations. Observed timestamps are evidence attributes, never the generation. Each attempt also freezes the authority-head fingerprint and archive-local authority-change journal incarnation described below; every verification references that same immutable attempt tuple.
- Immutable attempt identity/history; terminal invalidation reason/time, supersession relationship, and fresh verification identity bound to that exact attempt. One live attempt per operation; old tokens never reactivate.
- Durable reservation identity retained across failure, owner loss and takeover. Verified artifact/source hashes, old attempts and terminal outcomes are never deleted to release liability or manufacture a new attempt.

**Ledger-only is insufficient.** A generic release/reacquire or same-owner renewal can mutate the live row without changing a private ledger. Equal timestamps/owner are not proof that no mutation happened. The isolated harness must first demonstrate this false acceptance without a fence.

The proposed lease-mutation coverage (not complete authority-ABA coverage) is an additive, archive-scoped lease-mutation observer: INSERT/UPDATE/DELETE of the production-data-plane row invalidates any currently bound archive attempt affected by that row, atomically with the lease mutation. Even a same-values UPDATE invalidates; it does not trust a caller-supplied bypass GUC. It leaves legacy lease result/TTL/acquire/release semantics intact. For rows with no archive binding it creates no archive history. A binding can be invalidated only once; repeated generic mutations cannot append unlimited duplicate invalidations. Observer work is bounded by a unique active-binding index and MUST NOT take snapshot/quota/global locks while holding the lease row. Controlled renewal also invalidates the prior attempt, then installs a new binding/generation in the same controlled transaction; no old filesystem verification transfers to it.

This observer affects a shared table and is **not authorized for production or the next code slice**. Only a test-owned fixture may model it after this specification passes review. A future additive migration/trigger, definer role/ACL, rollback/reapply behavior, actual-owner integration and exact-code review require separate approval. Without an installed and verified observer or independently proved equivalent, real archive finalize remains disabled. A new ledger alone must never be presented as closure.

Expiry, release or backend/principal revocation invalidates eligibility even without a lease-row mutation. Finalization rechecks live server time and current authority under locks, AND requires unchanged captured authority-head/incarnation evidence. A currently active predicate alone cannot revive old verification after authority changed away and back. Release followed by reacquisition, same-owner renewal and expired takeover require a new archive binding/generation and fresh readback. A→B takeover requires explicit expected operation/attempt CAS after A is expired or verifiably revoked, preserving all history/reservation. B cannot preempt live A. Concurrent takeover has one winner; stale A and lost-response verification replay cannot finalize B's attempt. Restart under a still-valid attempt also requires fresh reopen/hash/decode verification. A matching already-terminal request may return its original receipt without re-eviction; conflicting identity refuses.

### Authority ABA while the lease is unchanged

The lease observer cannot see principal active→revoked→new active, backend active→retired→active, writer release A→B→A, or identity_fence_enabled true→false→true during file I/O. The lease owner/timestamps can remain unchanged throughout. Endpoint equality and a second current-active check are insufficient. The isolated fixture MUST demonstrate each of these failures in a lease-observer-only negative control before claiming any successor coverage.

The proposed fixture-only equivalent to an immutable authority incarnation has two parts:

1. Capture an immutable attempt-local authority-head fingerprint after locks: all latest-time principal binding IDs and their role/status/validity/configuration fields (deterministically ordered, refusing ambiguity), exact backend ID/principal/release/status/validity tuple, exact active writer-release tuple, and enabled settings tuple. A newer active principal binding has a different head; never silently replace the old attempt's captured head.
2. Maintain a private append-only **archive invalidation journal**. Every committed INSERT/UPDATE/DELETE on internal_principal_role_bindings_v3, stockinsider_backend_identities_v1, production_writer_releases and stockinsider_data_plane_settings_v1 appends an immutable unique event in the same transaction, including same-values UPDATE. TRUNCATE is refused in the fixture before mutation. The captured archive-local incarnation is the count AND deterministic hash of the complete ordered set of committed event identities/bindings, read after authority locks. It changes for every newly committed event even when values return to the original state. A conservative whole-journal fingerprint invalidates all pending verifications when any of these relations changes; narrower scoping is not approved here. The fixture bounds total event allocation with a fresh non-cycling sequence limited to128 slots: sequence gaps/aborts count against the workload bound, and exhaustion refuses. Sequence/max(event_id) alone is NOT an authority epoch: a lower-numbered concurrent event can commit after a higher one. The full committed event set detects that late commit. Events cannot update/delete/reset or be inserted by service callers. No mutable shared counter row is locked by observer triggers. Rollback removes its event; unused sequence slots do not themselves invalidate committed evidence.

The captured journal fingerprint and immutable history have only negative authority: they can invalidate a verification but cannot register a backend, mint a principal binding, enable settings, grant a role, sign a result or satisfy any existing active-authority predicate. They derive change detection from established relations and do not create a replacement trusted registry. In this slice they exist only in the disposable fixture, with explicit test identities and ACLs. Production installation is not presumed and is outside this approval.

Controlled acquire, verification registration and simulated terminal commit must compare both the immutable captured head and journal incarnation with fresh locked values. First attempts are permitted only after all observers/ACLs and the fresh fixture baseline are installed and verified. A change during I/O permanently rejects verification for the old attempt even when all relations again say active and bytes are identical. Restoring an old authority tuple, reusing its fingerprint, or copying a verified hash into a new attempt is forbidden. Continue only through an explicit new-attempt CAS under presently valid established authority, preserving the old attempt/invalidation and reservation, followed by a new real file reopen/decode/hash measurement bound to the new head/journal incarnation. An authority mismatch invalidates an archive attempt but does not authorize stealing an otherwise live legacy lease: a fresh-owner attempt must still satisfy the controlled acquisition/expiry/exact-owner release rules. Lost-response replay never upgrades old verification to the new incarnation. Already-terminal receipt retrieval is historical replay only and cannot cause a new terminal mutation.

Fixture authority observers only append their unique event after their own authority-relation mutation lock; they do not lock a mutable global counter, production lease, another authority relation, snapshot/quota state or archive operation row. Controlled transactions acquire all authority relation locks first, then freshly read the bounded immutable journal, then acquire subsequent snapshot/quota/operation locks. This avoids introducing a counter-row inversion between different legacy authority writers. Separate-session tests must include one lower-numbered event committing after a higher-numbered event and prove the full-set fingerprint detects it; unsupported writer lock sequences remain uncovered, not guessed safe. A scalable production projection over permanent event history is not designed or approved by this bounded fixture and cannot be replaced by max(sequence).

All four authority mutation surfaces, lease observer coverage, and required source/function/trigger identities must be enumerated in the report. Absent, disabled, unknown or partially modeled coverage means old verification refuses with an explicit uncovered-authority-transition outcome, proposedFenceCoverage remains incomplete and productionReady remains false. Catalog checks are not proof that privileged code never disabled/re-enabled an observer between operations. Such unobserved privileged DDL, changed observer definitions, out-of-protocol owner mutation or a lost journal history is outside this runtime proof and requires invalidating all earlier attempts/reviewing a new baseline; it cannot silently regain continuity. No fixture journal incarnation is exported as production trust material.

## 3. Proposed short-transaction lock profile to test

No file I/O, compression, network calls or operator wait may occur while holding these DB locks. This is a candidate profile, not a proven production lock protocol.

**Isolation precondition:** every controlled acquisition, renewal/takeover, verification-registration and simulated terminal fixture entrypoint MUST check current_setting('transaction_isolation') equals exactly 'read committed' before any mutation, authority lookup used for acceptance, idempotent early return or receipt reuse. Reject REPEATABLE READ, SERIALIZABLE and any other value; do not silently SET isolation or assume relation locks refresh a retained snapshot. This is an entrypoint contract, not just a connection-pool default. After acquiring relation locks, perform fresh authority/journal reads in subsequent READ COMMITTED SQL statements; no pre-lock cached result or outer-statement snapshot is acceptance evidence. Recheck the isolation setting and server-clock predicates immediately before simulated terminal mutation. Production portability of this behavior remains to be reviewed independently.

The required negative control uses actual two-session PG: A begins REPEATABLE READ and performs an authority SELECT to establish its snapshot; B commits a principal revocation before A acquires the proposed relation locks. A's unguarded predicate still sees the old active version despite the locks. Record that stale read, then prove the guarded entrypoint rejects A solely for unsupported isolation, with zero binding/verification/terminal writes. Repeat guarded rejection for SERIALIZABLE. A corresponding READ COMMITTED execution must freshly see B's committed revocation and reject on authority. No mocked clock/result or forced acceptance replaces these tests.

1. production_write_leases table SHARE ROW EXCLUSIVE, then select the exact row FOR UPDATE when present. The table lock covers the absent-row acquire/release gap and serializes ordinary legacy INSERT/UPDATE/DELETE as well as the observer. Global singleton lease contention is already intentional; measure impact and bound waits.
2. production_writer_releases table SHARE, then stockinsider_backend_identities_v1 table SHARE, then stockinsider_data_plane_settings_v1 table SHARE, then internal_principal_role_bindings_v3 table SHARE. Re-evaluate the exact active predicates after locks. Table-level predicate protection prevents new active/retired/revoked rows from bypassing current-row locks; do not silently substitute only row locks.
3. Freshly read the private authority journal fingerprint/count after all authority relation locks. For future snapshot mutation only: existing snapshot global advisory → dataset locks ascending; future reviewed shared quota lock → exact archive operation/binding/attempt rows. No code in this slice performs hot-raw mutation. The lease observer takes only its indexed archive binding rows after the lease mutation lock; authority observers append only unique journal events after their mutation locks, without a shared mutable counter row. Neither locks backwards into this chain.
4. Immediately before recording a simulated terminal outcome, recheck backend enabled/identity/release, unambiguous active principal, exact live lease and current binding generation, exact captured authority head and unchanged invalidation-journal incarnation against clock_timestamp(). Use finite lock/statement/transaction deadlines; timeout rolls back all ledger transitions and never releases reservation.

The first four authority relation locks must be tested against cutover's lease→writer→backend→settings order, runtime writer→backend rotation, bootstrap principal append, generic acquire/release, stale recovery and every known source lease caller. No operation may lock an archive ledger row and subsequently acquire an earlier lock. Lack of appropriate real definer privileges for a proposed table lock is a failed integration prerequisite, not permission to grant broad production rights. Owner/admin SQL outside the inventoried protocol, disabled triggers or disabled identity enforcement preclude activation. No locks protect against arbitrary superuser bypass; such authority is outside the runtime trust model.

## 4. Physical allocation and shared writers

The existing128MiB raw/32-snapshot bound is a logical hot SQL payload bound. It is not a4,000,000,000-byte physical source-evidence reservation or whole-host free-space guard.

Actual shared-store writers are web/src/lib/candidate-financial-artifact.ts:20–26 and web/src/lib/source-audit-artifact.ts:21–29: each writes first, then registers a receipt. The shared store allows64MiB objects (private-artifact-store.ts:6,75–99); the financial downloader allows50MiB (candidate-financial-documents.ts:7,96–116). Receipt registration at20260911_contabo_data_plane_v1.sql:257–279 has no capacity reservation and uses artifact_hash as a single-purpose primary key. It cannot establish independent archive-purpose bindings for equal physical content without an additive reviewed relation. Neither writer presently participates in archive shared reservations. Archive component failed staging is deliberately retained (insider-completed-archive-io-v2.ts:65–87).

A measurement report must keep these categories separate: logical raw bytes; encoded apparent bytes; physically allocated unique artifact/staging blocks; DB heap/TOAST/index allocation and growth; WAL generated and retained; transient filesystem copies; permanent historical metadata; unsettled reservation liabilities; host available disk/memory. No subtraction of logical raw bytes assumes PostgreSQL returned disk to the host. No deduction of two directory entries assumes two physical copies if they are the same inode. Conversely equal hashes at different inodes consume two allocations.

Instrumentation is real disposable PostgreSQL17 plus real local filesystem, not a JavaScript capacity simulation:

- Report exact server version, block_size, fs block size, wal_level, full_page_writes, wal_compression and checkpoint/settings profile; run an isolated checkpoint before measured mutation boundaries and disclose its effect. No production configuration changes.
- Per relation report pg_relation_size main/fsm/vm, pg_table_size, pg_indexes_size, pg_total_relation_size; enumerate reltoastrelid and its indexes separately as a decomposition, without double-counting inclusive totals. Include source document/receipt and proposed history tables, not just snapshot raw.
- Capture before/after pg_current_wal_insert_lsn and pg_wal_lsn_diff; report pg_stat_wal.wal_bytes separately after stats synchronization as a diagnostic, not a transaction-local cost. Measure allocated pg_wal directory separately; generated WAL is not retained physical WAL. Dedicated cluster and recorded background settings bound attribution; unavoidable noise is explicit.
- Enumerate only test-owned artifact/staging roots with lstat/no symlink traversal and finite entry/byte limits. Record dev/ino/nlink/size/blocks for real files, deduplicate physical blocks by dev+ino, and include directory allocation. Failure or unsupported stat fields refuses a physical result; never silently replace blocks with file size. Unlinked-but-open allocations need an explicitly tracked fixture FD or an unmeasured-liability flag, not omission.
- Record statfs(bavail*bsize) before/after and process/child memory samples/high-water data where available. Label sampling interval/missed-peak limits; RSS-at-end is not peak RSS. Whole-host admission retains the existing15GiB reserve/20GiB warning policy and memory guard (contabo-capacity-guard.mjs:4–30; contabo-host-resource-check.mjs:39–61).

A later candidate reservation formula must include permanent DB+history/index growth, physical raw/archive/staging copies, retained failed allocations, WAL/temporary/checkpoint margin and all concurrent source writers. Existing allocations and new reservations must not be double-counted, and no cancellation or historical deletion is added. This measurement slice emits observations and a coverage matrix, **not** an approved conservative4GB formula. An archive-only demonstration cannot certify a shared cap while financial/audit writers remain uncoordinated.

No runtime table, helper, route, package hook or persistent root is changed. Synthetic data and fixture-only identities are labelled fixtures, never model/owner/production authority receipts.
