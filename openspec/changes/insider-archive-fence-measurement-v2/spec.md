## 2. Required authority model and ABA closure

A future controlled archive acquisition must run inside one trusted DB transaction: resolve exact enabled backend/principal/release from authenticated server context, obtain a fresh server-generated lease owner, acquire the actual production-data-plane lease, lock and verify its live row, then register an archive-only binding/attempt. A request may select a snapshot; it cannot choose a trusted backend, principal, lease owner, generation, verified hash or receipt. Do not adopt an arbitrary existing live lease just because the caller can name its UUID. The deployed route must be able to supply this context without mutable global client headers leaking across requests.

Proposed private ledger identities are separate from legacy lease fields:

- Permanent operation ID and exact completed snapshot/raw/parser/rights binding.
- New non-reusable archive binding UUID and DB-maintained monotonic attempt generation for that operation; overflow refuses. Owner UUIDs generated for controlled acquisitions must never be reused in this ledger.
- Authenticated backend/principal/release plus exact lease key/owner and acquired_at/expires_at observations. Observed timestamps are evidence attributes, never the generation.
- Immutable attempt identity/history; terminal invalidation reason/time, supersession relationship, and fresh verification identity bound to that exact attempt. One live attempt per operation; old tokens never reactivate.
- Durable reservation identity retained across failure, owner loss and takeover. Verified artifact/source hashes, old attempts and terminal outcomes are never deleted to release liability or manufacture a new attempt.

**Ledger-only is insufficient.** A generic release/reacquire or same-owner renewal can mutate the live row without changing a private ledger. Equal timestamps/owner are not proof that no mutation happened. The isolated harness must first demonstrate this false acceptance without a fence.

The proposed enforceable successor is an additive, archive-scoped lease-mutation observer: INSERT/UPDATE/DELETE of the production-data-plane row invalidates any currently bound archive attempt affected by that row, atomically with the lease mutation. Even a same-values UPDATE invalidates; it does not trust a caller-supplied bypass GUC. It leaves legacy lease result/TTL/acquire/release semantics intact. For rows with no archive binding it creates no archive history. A binding can be invalidated only once; repeated generic mutations cannot append unlimited duplicate invalidations. Observer work is bounded by a unique active-binding index and MUST NOT take snapshot/quota/global locks while holding the lease row. Controlled renewal also invalidates the prior attempt, then installs a new binding/generation in the same controlled transaction; no old filesystem verification transfers to it.

This observer affects a shared table and is **not authorized for production or the next code slice**. Only a test-owned fixture may model it after this specification passes review. A future additive migration/trigger, definer role/ACL, rollback/reapply behavior, actual-owner integration and exact-code review require separate approval. Without an installed and verified observer or independently proved equivalent, real archive finalize remains disabled. A new ledger alone must never be presented as closure.

Expiry, release or backend/principal revocation invalidates eligibility even without a lease-row mutation. Finalization rechecks live server time and current authority under locks. Release followed by reacquisition, same-owner renewal and expired takeover require a new archive binding/generation and fresh readback. A→B takeover requires explicit expected operation/attempt CAS after A is expired or verifiably revoked, preserving all history/reservation. B cannot preempt live A. Concurrent takeover has one winner; stale A and lost-response verification replay cannot finalize B's attempt. Restart under a still-valid attempt also requires fresh reopen/hash/decode verification. A matching already-terminal request may return its original receipt without re-eviction; conflicting identity refuses.

## 3. Proposed short-transaction lock profile to test

No file I/O, compression, network calls or operator wait may occur while holding these DB locks. This is a candidate profile, not a proven production lock protocol.

1. production_write_leases table SHARE ROW EXCLUSIVE, then select the exact row FOR UPDATE when present. The table lock covers the absent-row acquire/release gap and serializes ordinary legacy INSERT/UPDATE/DELETE as well as the observer. Global singleton lease contention is already intentional; measure impact and bound waits.
2. production_writer_releases table SHARE, then stockinsider_backend_identities_v1 table SHARE, then stockinsider_data_plane_settings_v1 table SHARE, then internal_principal_role_bindings_v3 table SHARE. Re-evaluate the exact active predicates after locks. Table-level predicate protection prevents new active/retired/revoked rows from bypassing current-row locks; do not silently substitute only row locks.
3. For future snapshot mutation only: existing snapshot global advisory → dataset locks ascending; future reviewed shared quota lock → exact archive operation/binding/attempt rows. No code in this slice performs hot-raw mutation. The test observer takes only its indexed archive binding rows after the lease mutation lock, never locks backwards into this chain.
4. Immediately before recording a simulated terminal outcome, recheck backend enabled/identity/release, unambiguous active principal, exact live lease and current binding generation against clock_timestamp(). Use finite lock/statement/transaction deadlines; timeout rolls back all ledger transitions and never releases reservation.

The first four authority relation locks must be tested against cutover's lease→writer→backend→settings order, runtime writer→backend rotation, bootstrap principal append, generic acquire/release, stale recovery and every known source lease caller. No operation may lock an archive ledger row and subsequently acquire an earlier lock. Lack of appropriate real definer privileges for a proposed table lock is a failed integration prerequisite, not permission to grant broad production rights. Owner/admin SQL outside the inventoried protocol, disabled triggers or disabled identity enforcement preclude activation. No locks protect against arbitrary superuser bypass; such authority is outside the runtime trust model.

## 4. Physical allocation and shared writers

The existing128MiB raw/32-snapshot bound is a logical hot SQL payload bound. It is not a4,000,000,000-byte physical source-evidence reservation or whole-host free-space guard.

Actual shared-store writers are web/src/lib/candidate-financial-artifact.ts:20–26 and web/src/lib/source-audit-artifact.ts:21–29: each writes first, then registers a receipt. The shared store allows64MiB objects (private-artifact-store.ts:6,75–99); the financial downloader allows50MiB (candidate-financial-documents.ts:7,96–116). Receipt registration at20260911_contabo_data_plane_v1.sql:257–279 has no capacity reservation and uses artifact_hash as a single-purpose primary key. It cannot establish independent archive-purpose bindings for equal physical content without an additive reviewed relation. Neither writer presently participates in archive shared reservations. Archive component failed staging is deliberately retained (insider-completed-archive-io-v2.ts:65–87).

A measurement report must keep these categories separate: logical raw bytes; encoded apparent bytes; physically allocated unique artifact/staging blocks; DB heap/TOAST/index allocation and growth; WAL generated and retained; transient filesystem copies; permanent historical metadata; unsettled reservation liabilities; host available disk/memory. No subtraction of logical raw bytes assumes PostgreSQL returned disk to the host. No deduction of two directory entries assumes two physical copies if they are the same inode. Conversely equal hashes at different inodes consume two allocations.

Instrumentation is real disposable PostgreSQL17 plus real local filesystem, not a JavaScript capacity simulation:

- Report exact server version, block_size, fs block size, wal_level, full_page_writes, wal_compression and checkpoint/settings profile; run an isolated checkpoint before measured mutation boundaries and disclose its effect. No production configuration changes.
- Per relation report pg_relation_size main/fsm/vm, pg_table_size, pg_indexes_size, pg_total_relation_size; enumerate reltoastrelid and its indexes separately as a decomposition, without double-counting inclusive totals. Include source document/receipt and proposed history tables, not just snapshot raw.
- Capture before/after pg_current_wal_insert_lsn and pg_wal_lsn_diff; report pg_stat_wal.wal_bytes separately after stats synchronization as a diagnostic, not a transaction-local cost. Measure allocated pg_wal directory separately; generated WAL is not retained physical WAL. Dedicated cluster and recorded background settings bound attribution; unavoidable noise is explicit.
- Enumerate only test-owned artifact/staging roots with lstat/no symlink traversal and finite entry/byte limits. Record dev/ino/nlink/size/blocks for real files, deduplicate physical blocks by dev+ino, and include directory allocation. Failure or unsupported stat fields refuses a physical result; never silently replace blocks with file size. Unlinked-but-open allocations need an explicitly tracked fixture FD or an unmeasured-liability flag, not omission.
- Record statfs(bavail*bsize) before/after and process/child memory samples/high-water data where available. Label sampling interval/missed-peak limits; RSS-at-end is not peak RSS. Whole-host admission retains the existing15GiB reserve/20GiB warning policy and memory guard (contabo-capacity-guard.mjs:4–30; contabo-host-resource-check.mjs:39–61).

A later candidate reservation formula must include permanent DB+history/index growth, physical raw/archive/staging copies, retained failed allocations, WAL/temporary/checkpoint margin and all concurrent source writers. Existing allocations and new reservations must not be double-counted, and no cancellation or historical deletion is added. This measurement slice emits observations and a coverage matrix, **not** an approved conservative4GB formula. An archive-only demonstration cannot certify a shared cap while financial/audit writers remain uncoordinated.

## 5. Finite isolated harness and acceptance

After independent requirements/design PASS, implementation may add only the paths declared in plan.md. Use existing test lifecycle helpers read-only; real PG/large payload runs queue on the VM. No runtime table, helper, route, package hook or persistent root is changed. Synthetic data and fixture-only identities are labelled fixtures, never model/owner/production authority receipts.

Bound each VM invocation to240 seconds plus10 seconds cleanup; max32 simulated operations,64 attempts,128 ledger events,16 measured cases, three concurrent DB sessions,96MiB simultaneous synthetic source payload,512MiB new artifact/staging allocation and4GiB total disposable-cluster workspace. Refuse before crossing any harness bound. Large50/64MiB writer cases run sequentially after retiring only disposable fixture bytes, and cannot overlap another heavyweight queue item. Limits are harness controls, not new retention policies. Report unknown disk/WAL peaks honestly; a monitor crossing its safety budget fails/stops the test, it does not certify a hard kernel allocation cap.

Named required checks:

- AFM-01 ledger-only negative control: legacy same-owner renewal and release/reacquire can bypass timestamp-only binding; preserve the actual RED outcome. Include release/reacquire inside one transaction where NOW() is unchanged. No production bypass is executed.
- AFM-02 observed-mutation closure: proposed fixture observer invalidates old attempt for same-values UPDATE, same-owner renewal, DELETE/reinsert and expired takeover; rolled-back mutation does not falsely revoke a committed binding.
- AFM-03 controlled acquisition binds a fresh owner/backend and independent generation atomically; duplicate retry gives exact original result, arbitrary existing lease adoption and caller identities reject. Terminal binding IDs never reuse.
- AFM-04 A→B CAS, two racing B/C claimants, stale A replay, prior verification replay, restart, expired lease, disabled/NULL backend and changed release/principal all reject or produce one exact winner without losing reservation/history.
- AFM-05 principal append phantom: a newer revoked or ambiguous same-time binding must serialize/refuse; current-row-only negative control demonstrates why it is inadequate. Frozen inactive role fixtures do not imply real registered authority.
- AFM-06 actual lock interleavings use separate sessions/barriers and pg_locks evidence, not sleeps alone: generic release/acquire, stale recovery read→release, cutover order, runtime rotation, bootstrap append and proposed terminal writes. Finite lock timeout fails closed; no deadlock/partial terminal mutation.
- AFM-07 raw2/12MiB, compressible/incompressible bytes, encoded maximum, cross-observation duplicate and distinct content preserve bytes/clocks; physical inode dedup is independent of observed identity.
- AFM-08 publication phase measurements before stage/write/fsync/link/verify/cleanup, retained failed stage, concurrent same-hash and different-hash writers, orphan and tracked-open-unlinked file: actual allocations and liabilities remain accounted. No fixture result authorizes DB eviction.
- AFM-09 actual existing financial/audit store calls with fixture receipt transport, including50MiB financial and64MiB shared-store limits/+1. Source/runtime/receipt stubs and fixture ACL differences are explicit. Demonstrate that unfenced legacy writers defeat an archive-only reservation; do not label it shared-cap PASS.
- AFM-10 heap/TOAST/index/WAL metrics reconcile their decomposition without inclusive-total double counting; no assumed disk credit from logical deletion. Arithmetic exact/+1 reservation examples use observed fixture facts but do not approve a production formula.
- AFM-11 receipt/cleanup integrity: child check failure, timeout/cancel, missing metric, growing tree, unsafe path, process-close failure or log overflow cannot produce passed:true. All required outcomes and owned-child cleanup precede final verdict.

Negative controls pass only when the intended defect is witnessed, and their actual rejection/false-acceptance observations are retained. Missing PG/tools is an explicit failure, never a skip or green substitute. No unsigned test report is promoted to protected release or independent approval evidence.
