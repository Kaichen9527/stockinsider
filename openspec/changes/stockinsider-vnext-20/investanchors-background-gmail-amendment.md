# InvestAnchors background Gmail notice scan

The internal operator action uses Google's OAuth refresh endpoint with fixed URLs and no redirects. It requires the explicit `gmail.readonly` grant and checks the Gmail profile against the configured mailbox fingerprint before listing. The Gmail writer adapter accepts only the fixed publisher query for the selected Taipei date and fetches full MIME only for IDs returned by that listing. Private mail fields, account names and credentials remain outside the public surface. The action responds with uncached operational counts and separate article authority.

When explicitly enabled, the existing 08:15 Taipei timer runs this notice scan after its market-background step. The two outcomes are reported independently. The notice scan first recovers the oldest incomplete closed Taipei day. The same morning invocation also requests the current Taipei day with a separate writer lease and logs its result independently. An open day never establishes an early checkpoint. The authenticated operator can specify one closed date within the existing 30-day receipt window for recovery. The 21:30 schedule and systemd timer definitions are preserved.

Deployment defaults to disabled. The configuration uses the existing service's protected environment with `STOCKINSIDER_INVESTANCHORS_GMAIL_CLIENT_ID`, `STOCKINSIDER_INVESTANCHORS_GMAIL_CLIENT_SECRET`, `STOCKINSIDER_INVESTANCHORS_GMAIL_REFRESH_TOKEN`, `STOCKINSIDER_INVESTANCHORS_GMAIL_MAILBOX_SHA256` and `STOCKINSIDER_INVESTANCHORS_NOTICE_HMAC_HEX`. Use a dedicated offline grant for the intended mailbox with the exact read-only scope. The mailbox fingerprint is SHA-256 of the trimmed lower-case Gmail profile address. The notice key is a separate 32-byte secret. Store sensitive values only in the protected environment. Once staging verifies the exchange, `STOCKINSIDER_VNEXT_INVESTANCHORS_GMAIL_ENABLED=true` enables the optional scheduled step. The interactive Gmail connector is separate from this background OAuth grant. [Google OAuth offline access](https://developers.google.com/identity/protocols/oauth2/web-server#offline) · [Gmail API scopes](https://developers.google.com/workspace/gmail/api/auth/scopes) · [Gmail profile method](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users/getProfile)

This flow stops at the notice ledger. The member article needs its own authorized supply and original publication and acquisition evidence. The focused tests use a mocked provider, and the production configuration check confirms the required background OAuth fields are absent and the feature is off.
