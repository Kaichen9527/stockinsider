## Atomicity, CAS, idempotency and retention

One DB transaction under the original global authority lock checks request replay first, then compares the latest chain head to expectedPreviousRankingRunId. The same rankingRunId+principal+request returns the original immutable historical receipt; any conflicting reuse rejects. Different run IDs using one predecessor serialize: one may insert, the other rejects CAS. A unique coalesced predecessor index additionally prevents two successors and duplicate genesis. No mutable head pointer exists; readers select the committed greatest ordinal. Identity sequence gaps after rollback are harmless.

`vnext_ranking_snapshots_v1` appends snapshot JSON plus server input/request hashes and cutoff. Snapshot contains rankingRunId, previousRankingRunId, cutoff, original policy, market/price/financial/score/research revisions, frozen market, ranked pointers and entered/exited/maintained reasons. No raw source evidence, provider request or private execution identity is copied into ranked/candidate rows.

`vnext_ranking_members_v1` creates real relational FK retention pins for every frozen candidate publication pointer (all active<=20, including members outside Top10). Rank is nullable for nonranked members and unique1–10 when present. The same transaction inserts snapshot, pins and existing writer-fenced audit event; any failure rolls everything back. No research job/attempt counter is started or charged.

Both new tables use the original no-login vNext owner, RLS enabled, all direct privileges revoked from PUBLIC/anon/authenticated/service_role, original writer-fence trigger and unconditional UPDATE/DELETE/TRUNCATE rejection. The existing owner bypass behavior is the original owner pattern; no new role or permissive public policy is created. The exact source preflight pins dependency body hashes/owner/proconfig/security-definer state from existing source profiles or complete original constructors, including TimeZone behavior. It does not change existing pins.
