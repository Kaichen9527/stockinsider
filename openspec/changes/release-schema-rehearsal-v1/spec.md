# Reviewed schema rehearsal and ownership bridge

This implements the authorized release-repair scope; it grants no protected
attestation, runtime bootstrap, strategy adoption or production permission.

Research extension order is a separately hashed finite ownership prelude,
unchanged approved V3 migration paths, then existing research/Cloud/history tails.
The reviewed runner still requires a clean exact source, reviewed release
attestation, explicit research authority, predecessor checks and one atomic
transaction including installation verification. There is no raw production runner.

Only five exact public signatures may transfer from `postgres` to the owner
already required by tracked SQL. Every existing function must match finite raw
`prosrc` SHA256 profiles, signature, argument names, result, language, volatility,
SECURITY DEFINER, non-STRICT/non-leakproof/unsafe-parallel flags and empty search
path. Target roles must remain NOLOGIN, nonsuperuser, non-BYPASSRLS and unable to
create public objects. Default-public/unknown/grantable ACLs reject. All profiles
and caller ownership authority validate before any owner mutation. CREATE is
granted only during each owner transfer and revoked in the same transaction.
No function body, financial/stock row, source evidence, timestamp or membership
is changed by the bridge. Missing functions on fresh installs are no-ops.

The preserved V3.19 routine admits exactly two independently compared raw body
hashes. Its observed variant differs from tracked reconstruction only in two
explicit token-separating formatting spans; no global whitespace normalization
or arbitrary production-body acceptance is used.

Existing runtime roles must satisfy the original reviewed nine-RPC login
contract before the first migration mutation. Invalid existing role bootstrap
is reported, never repaired by silently enabling login or creating credentials.
Absent-routine supersession detection must safely return false.

Technical identity hashing uses `extensions.digest`, matching actual deployment
and the rest of V3. The execution release manifest is regenerated; unchanged
strategy parameters do not authorize adoption of a new source/code version.

Acceptance uses real disposable PostgreSQL: exact tracked-profile transfers,
no-op/replay, non-owner login, altered body/security/search path, public execution,
powerful target role, and failure rollback. A read-only production schema export
can rehearse the compound plan locally with no production rows. Original owners,
ACLs, simulated role attributes and known bootstrap differences must be recorded
separately. Only a frozen clean source and actual ordered file hashes constitute
the local source identity. Such a rehearsal is not protected approval, least
privilege deployment proof or a financial data migration acceptance.
