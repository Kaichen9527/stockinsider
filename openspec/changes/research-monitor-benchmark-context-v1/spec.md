Root owns the new adapter, focused tests, technical snapshot integration and necessary test-command membership. VM owns publication/input work; no shared-file reversal is permitted.

## Problem and scope

The existing qualified/held worklist and per-symbol controller already exist. The actual technical snapshot resolves official common-stock identity, adjusted OHLCV and calendar but does not read benchmark observations. This slice supplies real server-read benchmark context through that existing route. It does not introduce a controller, database, public API, collector, provider, strategy threshold, order, qualification or publication authority. Official institutional net-share data requires a separate schema/writer amendment; do not pass TWD flows into share-volume ratios or fill missing chips with zero.

## Fixed contract

1. Resolve identity/exchange/session/cutoff only through the existing server route. TWSE uses official `taiex_close / TAIEX / twse / index_points`; TPEX uses `otc_close / OTC / tpex / index_points`. No FinMind/node-twstock/other-market fallback. No caller benchmark selection.
2. Require the existing authority to have verified signal-session price basis, no missing data, its fixed source dataset revision, and240 adjusted bars. Use its final61 completed sessions, aligned exactly to the final61 stock bars, ending at the signal session; each bar remains available no later than cutoff. No five-row pseudo-week, skipped holiday filler, forward fill or partial shortened return.
3. Read `tw_trading_sessions_v3` for those61 dates at the same cutoff, including completed/cancelled rows before selecting heads. Validate official market/provider, real dates, UUIDs, source references, open/close in the matching Taipei civil date, source/collection/record order and all clocks<=cutoff. Select the latest recorded head for each date; a cancelled, conflicting or incomplete selected head makes context unavailable. Semantically identical equal-time calendar heads choose the smallest ASCII UUID; conflicts reject. This independent calendar must have exactly the same completed date sequence as the stock authority.
4. Read official `opportunity_market_observations_v3` for those dates/fact/scope/provider/unit, with observed/collection/record clocks<=cutoff. Require positive finite index value, null foreign-provider identity/date, authority_date=session, observation UUID, nonempty bounded source_ref/provider_revision, and exact selected calendar authority ID. observed_at must be at or after that session's official close. A row for an obsolete calendar head cannot supply the selected head.
5. Select the latest recorded market observation per session (official stream revision order), then require its calendar binding. Do not silently use an older observation if the latest one binds an obsolete calendar. Same-recorded-time candidates with different values, provenance, units, calendar identities or observed/collection clocks are conflicts; semantically identical ties choose the smallest ASCII UUID deterministically. Preserve all selected observation identities/clocks/revisions in the context evidence hash. Future revisions are excluded, not retrospectively used.
6. Preserve PostgreSQL microseconds with the existing exact `researchDeepInstant` parser for ordering/cutoffs; unsupported precision rejects explicitly rather than truncating. All source/cutoff strings are bounded. Do not change the existing live authority's formulas or timestamp implementation in this slice.
7. Calculate5/20/60 **completed-session** returns from6/21/61 aligned endpoints. Formula is relative wealth ratio minus one: `(adjustedStockEnd/adjustedStockStart)/(priceIndexEnd/priceIndexStart)-1`, unit `fraction`. Also return stock and index price-return fractions separately. This matches the existing discovery ratio convention and differs from a percentage-point spread. It is adjusted-price versus price-index context, not total return, alpha, expected profit or causal evidence. All61 points must be available even for the5-session field; otherwise all returns are null with a concrete reason.
8. Output `research-monitor-benchmark-context-v1`, benchmark identity/formula/unit, source dataset/price basis/calendar bindings, selected evidence hash/context hash,61-session coverage,5/20/60 fields, `available` and bounded missing reasons. Unavailable/read failure/conflict/bound exceeded is explicit, never zero relative strength or successful-empty. This adapter reads only; it cannot establish trusted model or strategy authority.
9. Store the context in the existing technical snapshot JSON; bind its version and context hash into decision_input_hash. Existing technical formulas, parameters, thresholds, qualification rules, held-position risk behavior and finalDatasetConfirmed semantics remain unchanged; statistics alone cannot promote a signal or qualification. The route belongs to the existing strategy source graph, so normally regenerate the tracked release identity using the existing tool. The resulting new codeHash does NOT inherit old strategy approval. Existing governance must reject the old approval and leave entry blocked unless the user approves the exact new release; this increment creates no approval or strategy adoption. With no new approval, context may still be saved for monitoring. A missing context stays visible even if pre-existing price-only analysis succeeds. Replay with identical inputs produces the same context identity; a known correction changes it. No migration or historical receipt rewrite.
10. Bound each database read to500-row pages plus overflow sentinel: calendar4096 rows, benchmark3904 rows (61×64 existing market revisions), combined serialized input from ALL read rows before head selection at most8MiB; bounded references<=4096UTF8bytes and clocks<=40bytes. Each calendar query has a unique total order `(session_id ascending, recorded_at descending, session_authority_id ascending)`; market queries use `(session_id ascending, recorded_at descending, observation_id ascending)`, with precise database timestamp order. All pages share the fixed cutoff and one monotonic15-second adapter deadline/AbortController. Pass the abort signal to each actual database request, race nonresponsive requests against the deadline, discard late responses, and start no page after expiry. Client timeout is not proof a remote server query stopped. Sort/group, never pairwise scan. Query errors, deadline, partial/bound-exceeded data or unsupported rows produce typed unavailable reasons. No unbounded global-market history reads or new host cache. The root package research test command may append only the new focused tests; existing route/test expectations may gain the new read dependency without weakening prior assertions.

## Acceptance

- Pure adapter: TWSE/TPEX official complete61-session positive cases and known numeric5/20/60 results; ratio vs percentage-point distinction; calendar/market revision corrections change context identity; permutations and exact replay agree.
- Missing one date, cancelled latest calendar, wrong market/provider/unit, nonpositive values, wrong calendar head, future/precision-invalid clocks, conflicting equal-time heads, partial pagination/overflow/read failure and over-byte-bound inputs are unavailable; no zero substitution.
- Calendar correction without a corresponding newly bound market revision is unavailable; adding the matching known revision restores context. Equal-time calendar ties follow the explicit deterministic semantic rule. Conflicting heads split across pages still reject.
- Stalled read and late success cannot exceed/override the shared deadline or start another page. Row/byte exact-bound and+1 overflow sentinels include every read revision, not only selected heads.
- Short weeks/holidays use existing official completed dates. Stock corporate-action basis or source revision changes bind a new context; unavailable stock authority never becomes valid because a benchmark exists.
- Existing route contract keeps exact auth before DB reads and fixed historical cutoff; the actual route persists the same server-derived context and decision hash. Qualified and held monitor worklists remain intact; no strategy qualification/entry promotion.
- Normally regenerated source codeHash rejects prior release approval. Without a new user approval, benchmark context is saved while new entry remains blocked; no approval receipt is minted and old held-position ownership/version remains.
- VM actual PostgreSQL/PostgREST plus actual guarded technical route: complete context, one missing session, correction/replay, wrong calendar and authorization/no-write cases. Synthetic fixture and explicit privileges must be identified; source collector activation and production ACL are not inferred.
- Focused/unchanged relevant tests, typecheck, lint and normal build pass on exact code; independent code review before any adoption. No main merge, production deployment, live scheduler or profit claim from this increment.
